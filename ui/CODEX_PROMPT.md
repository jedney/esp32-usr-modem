# Codex task — Implement the Sportster 14.4k/28.8k/33.6k/56k BBS UI

v0.12 integration: C opens Client Tests on serial; the browser lists them without
execution. The catalogue now has 72 nested actions (57 original plus 15 client
actions). This supersedes the original disabled-placeholder instructions below.


I have added the `ui/` design package to this repository.

**Task:** Implement the **USRobotics Sportster 14.4k/28.8k/33.6k/56k configuration interface**, based on `ui/DESIGN_SPEC.md`, `ui/theme-tokens.json`, `ui/menu-definition.json`, and the two PNG wide-layout visual references in `ui/assets/`. The reference mock-ups are `reference-main-menu.png` and `reference-phonebook.png`; the original red logo source is `us-robotics-logo-original.svg`. **The `ui/previews/` screens are the measured 80×25 design reference and take priority over the wide PNGs for 80×25 layout.**

**First inspect the repo** and determine its existing language, rendering path (ANSI terminal, web terminal or other), navigation conventions, `AT*MODEL` implementation, real device/state interfaces, tests, and screen-size constraints. Work within that architecture; do not rewrite the app or invent API endpoints. Ask only if a missing decision blocks an essential feature.

Priorities:

1. **Make 80×25 a first-class target.** A physical 80-column × 25-row terminal must display the entire 13-option main menu in two compact text columns, without wraps/clipping or horizontal scrolling. Use the five-row red cell-art wordmark on the main menu, compact one-line red wordmark on submenus, fixed white frames, cyan titles, green hotkeys, blue function-key hints, persistent status and `Command >` area. Follow `ui/DESIGN_SPEC.md` §3 and the exact grid in `ui/previews/main-sportster-28.8k.txt` / `.ans`. Do not copy the wide PNG geometry into 80×25.
2. **Support all four runtime model themes.** Logo always red. Select the model/title/accent from the **existing active state associated with `AT*MODEL`**: `Sportster 14.4k Series` `#6f327f`; `Sportster 28.8k Series` `#448FA1`; `Sportster 33.6k Series` `#349b67`; `Sportster 56k Series` `#3F668E`. Preserve these exact values when RGB is possible and use reasonable ANSI approximations otherwise. **Do not assume the AT command syntax or its parameter values**; inspect the implementation. If model is unresolved, display `Unknown` explicitly rather than making up a default.
3. Render every main-menu entry from `ui/menu-definition.json`. At **wide sizes** (ideally 120–132 columns and enough rows), match the 28.8k *two-column rich-card reference*. At **80×25**, use the compact two-column text-only main menu with all options visible. `Client Tests` must be visibly `UNAVAILABLE`, skipped by navigation and incapable of running via hotkey/Enter.
4. Implement Phonebook according to the wide reference when space permits: selectable entries table, command stack, dynamic selected-entry details and four nested actions. At 80×25, use the compact full-width list with **up to nine visible entries per page**, details summary, paging and contextual actions; `I` can open full details. Do not add fake production contacts; use the existing service/store or a clearly labelled DEMO fixture. Make delete/dial disabled without selection and confirm destructive/dial actions.
5. Render every remaining menu with its **complete 72-item nested inventory** from JSON. At 80×25, one-line entries let Settings (13), Wi-Fi and Clock (12), and Hardware Tests (15) remain on one screen. Scroll/paginate future longer lists and preserve selection on Back. Wire supported actions via existing services. Leave unsupported options reachable, mark action unavailable, and name the missing service hook; never pretend an unsupported action succeeded.
6. Wire hotkeys, arrow keys, Enter, Esc, Q and **contextual** F-keys; do not capture typing in forms. Hints must always represent actual working controls. Use the host's existing terminal escape sequence conventions. Preserve selection and scroll state on Back and handle terminal resize.
7. Show only real device/state values in status/profile/footer. No fake serial numbers, timestamps, COM/IRQ, rates, carrier flags, phones or IP addresses from mock-ups. Use `--` or `Unknown` if unavailable. Respect secrets, password entry/security, cancellation, async states and confirmations around delete, reset, restart, dialing, firmware/network/profile changes.
8. If terminal is 120–132 columns with adequate height, add the enhanced layout. For intermediate widths, make a controlled compact/wide choice. For smaller than 80×25, degrade safely instead of overflowing. For all sizes, render measured **cell widths**, not Unicode byte/string lengths, and avoid terminal auto-wrap at last row/column.
9. Test navigation, full menu inventory, four themes, disabled states, model changes, terminal geometry (80×25, 79×25, 80×24, 100×25, 120×45, 132×50), phonebook paging/selection, state-bound footer, password safety, confirmations and selection preservation. Run existing repo tests. Static preview tests in `ui/tests/` are design contracts, not substitutes for real UI tests.

**Never ship the generated PNG as a static UI.** These images are references only. The SVG is directly usable in browser-based rendering, but real ANSI terminals need character-cell art. The `.txt` and `.ans` previews document screen geometry; they do not implement device commands or application routing.

**When done**, summarize changed implementation files, working versus unsupported functions, how the device selects the model with `AT*MODEL`, 80×25 versus wide-screen behavior, keyboard controls, tests run and commands to run them. If a feature cannot be implemented from available APIs, make its screen reachable, explicitly label that action unavailable, and describe the needed service hook.
