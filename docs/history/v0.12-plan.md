## Implementation sequence

### 1. Portable diagnostic model and serial lifecycle

- Add hardware-independent diagnostic state machines in a new `lib/clienttest/`,
  with interfaces for clock, byte transport, signals, sources and settings storage.
  Keep Arduino, filesystem and GPIO access behind `lib/hw` adapters.
- Share the same diagnostic operations between menu actions and the AT* registry;
  extend `AT*HELP`, reference output and parity tests. Brief examples such as
  `AT*TEST SIZE`, `AT*TEST KEYS`, `AT*SX`, `AT*SZ` and `AT*RZ` are starting points;
  document the final grammar, variants, size/duration limits and cancellation.
  Check the current 64-entry registry capacity before adding commands.
- Reuse `hostport::Session::startLocal` and `CallSlot` ownership. Introduce an
  explicit diagnostic byte-routing state within the local service so menu key
  decoding, geometry probes, redraws, result paging, echo, unsolicited console
  notices and AT parsing cannot intercept or inject protocol bytes.
- The existing local-session path bypasses the online software-flow/escape path;
  verify this deliberately. Protocol payload may contain XON/XOFF, CAN, Ctrl-C,
  ESC and `+++`. Interpret cancellation according to the active protocol, with
  bounded idle/overall timeouts, rather than treating arbitrary payload as keys.
- Snapshot temporary UART/flow/signal/UI settings and restore them on completion,
  failure, cancellation, DTR loss and service exit. Do not overwrite saved modem
  settings as a side effect. Every blocked transmit/drain must have a deadline.
- Keep Wi-Fi, HTTP status, clock and watchdog serviced during long tests. Browser
  status should identify Client test while commands/uploads remain unavailable.

### 2. Display, geometry, identification and keyboard tests

- Implement ANSI's 16 foreground/background colours, bright/bold, underline,
  reverse, blink, cursor movement and clear-screen/line patterns; CP437's complete
  table, box drawing and shading; ASCII-only Plain; and a Latin-1 table.
- Separate terminal presentation style from character encoding. Show raw test
  glyphs intentionally without allowing received strings to become control
  sequences. User confirmation determines visible support; successful output
  alone is not proof that a terminal displayed it correctly.
- Measure using cursor-to-999,999 plus `ESC[6n`, accepting bounded fragmented CPR
  replies for approximately one second. On no/invalid reply, show a ruler and ask
  for visible columns/rows. Restore cursor/screen state. Retain the bundled
  `CSI 18 t`/`CSI 8;rows;cols t` support; distinguish those reports from CPR.
- Record measured geometry separately from the renderer's supported viewport
  (currently capped at 132x50). Do not report a capped view as the physical size.
- Capture ENQ answerback, DA (`ESC[c`) and DSR (`ESC[5n`) replies with bounded
  buffers/timeouts; display received bytes safely as escaped/hex data. No reply
  means unsupported/unknown rather than a guessed terminal type.
- Keyboard mode reports raw codes for BS/DEL, arrows, Delete, function keys and
  CR/CRLF, with a clearly advertised termination key and timeout. Prevent late
  replies or the terminating key from activating the restored menu.
- Provide line-ending/local-echo patterns, BEL and a serial-speed/format report.
  Distinguish user observations from measured findings. No serial-format claim
  may exceed what the actual UART configuration/detection provides.

### 3. Throughput, flow control and cable diagnostics

- Add bounded transmit/receive throughput tests, reporting actual completed byte
  counts, elapsed time and characters per second. State whether counts include
  protocol framing; queueing bytes alone is not completed transmission.
- On COM18 measure RTS pause transitions/duration and receive backpressure/CTS
  behavior. Include a peer that deliberately holds RTS and obeys CTS. Report
  console hardware-handshake fields as unavailable: its USB-serial control lines
  are associated with ESP reset/boot, not the host RS232 cable.
- On RS232 show DTR/RTS and toggle DCD/RI/CTS with bounded dwell/automatic restore,
  describing DSR as hard-wired asserted. A CTS-off test needs a timed recovery even
  if its own output is paused. Expect some terminals to react to carrier changes.
- Reuse signal interfaces and ownership checks without enabling Q79's disruptive
  raw line/loopback/bridge hardware tests inside an RS232 menu. Client cable tests
  must retain the active UART and recover independently of terminal input.
- Console cable diagnostics may exercise the separately connected COM18 peer
  while owning the slot; describe clearly which cable/port is being measured.
  No diagnostic takes over an existing call or another port's service.

### 4. File-transfer engine and sources

- Retrieve and inspect Zimodem `proto_xmodem`/`proto_zmodem` at an immutable
  revision, starting with the repository's existing Telnet-source revision
  `a534e5129d88b8b09aa01fe17498d5cd5368569e`. Verify actual source filenames,
  dependencies and supported variants before porting; upstream transfer files
  were not retrieved successfully during this planning pass.
- Retain original headers, mark modifications and update `credits/LICENSES.md`
  plus accompanying notices. Q75 already accepts the ZMODEM source licensing;
  no new licensing decision is needed. Add the X/YMODEM record when code is added.
- Adapt the protocol core to incremental, bounded input/output and injected
  sources/sinks, removing SD-shell coupling. Implement XMODEM checksum, CRC and
  1K; YMODEM batch with filename/size; and ZMODEM in both directions.
- Downloads use an immutable secret-free PSRAM-log snapshot named `USRMODEM.LOG`,
  allowlisted LittleFS sounds with DOS-safe 8.3 aliases, or a streaming deterministic
  generated file of the user's chosen bounded size (including 64 KiB and 1 MiB).
  Do not build a megabyte payload in RAM. Batch selection uses the same sources.
- Receives validate framing/checksum/CRC and count accepted bytes while discarding
  payload. Never create a filesystem file or use peer-provided paths. Arbitrary
  uploads can be checked for transport integrity; only known generated fixtures
  permit independent content comparison. For XMODEM, report block padding/unknown
  original length honestly because it carries no filename/length metadata.
- Report bytes, elapsed time, characters per second, retries/errors and final
  success/cancel/timeout. Count retransmissions separately from unique payload.
  Bound filename/header lengths, advertised sizes, batch work, retries and idle
  time; disable protocol features outside file transfer, such as command execution.
- Defer all text and UI redraw until the protocol ends and its output drains.
  Exercise binary bytes across the full 0-255 range and protocol-looking payload.

### 5. Results, saved settings and shared UI integration

- Add a real Client Tests screen at stable root ID `client-tests`, key D. Remove
  the serial placeholder and hard-coded unavailable footer text. Browser D opens
  a read-only listing with the serial-only explanation; execution is rejected
  by firmware even for forged browser input/direct AT* invocation.
- Extend `ui/menu-definition.json`, bindings, generated C++/browser catalogue,
  demo, previews and contracts together. Preserve the 80x25 layout, four model
  themes, plain fallback and adaptive browser behavior. Update the old exact
  57-child inventory expectations to the new explicit action inventory.
- Summary distinguishes pass/fail/unknown/manual/unavailable/cancelled and shows
  findings without silently changing settings. Offer confirmed apply/save for
  character set, dimensions and Backspace. Use one independent saved record each
  for console and RS232, selected by the active physical port. Changing attached
  computers does not switch records; the user can retest and replace that port's
  saved findings with confirmation.
- Use a versioned, checked persistent record with rollback on failed save, sensible
  defaults for absent/corrupt/older storage and tests for reboot retention. Define
  query/apply/save/reset commands and secret-free export/factory-reset integration.
  Avoid writing flash on every key/probe. Existing AT*STYLE and AT*SIZE remain
  deliberate local overrides with documented precedence over saved defaults.
- Apply the chosen Backspace behavior to the menu editor and review the AT editor
  for consistent client input behavior. Latin-1 glyph settings must not remove
  required ANSI/Plain fallbacks or affect modem wire protocol data.

- 361 native checks pass, including 19 client-service/protocol checks and 25
  real-renderer/menu checks. Recovery covers corrupt blocks, lost acknowledgments,

  Client key aliases preserve the standard S5 setting.
- 22 Node, nine Python script and five design-contract checks pass. Formatting,
  cppcheck's medium-severity gate, firmware/LittleFS builds and image manifests pass.
- Three new wired-safe on-board checks pass: scratch NVS profiles, immutable log /

  compile; compile-only runs report SKIPPED, not executed acceptance.
- Independent lrzsz acceptance passes 12 cases each against Ubuntu 0.12.21rc and

  and binary content/CRC checks. Current upstream is installed under ignored
  `.pio/tools/lrzsz-installed` in addition to Ubuntu's package.
- All ten final COM18 transfers pass with independent current lrzsz, verified
  content/CRC, and zero retries/errors. A Windows pyserial / WSL stdio bridge opens
  COM18 only on Windows and reports the Linux peer's explicit exit status.
- Nine COM15/COM18 client cases pass, including confirmed independent saved
  profiles across reboot (original records restored), CPR/manual size, raw keys,
  reservation, bell prompt, RTS pause accounting and real DCD/RI/CTS restoration.
- Existing full regression passed 127 cases with 14 skips; its single failing CSRF

  its single failure exposed an E2E WebSocket reader consuming partial headers on
  timeout. The reader now retains entire partial frames, with a script regression;
  the final browser rerun passes all 16 cases with one opt-in install skip.
- The real renderer's compact Client Tests and wide Main images were inspected;
  all fifteen client actions fit 80x25. Runtime captures remain ignored under
  `.pio/ui-snapshots/`.
- Normal v0.12 firmware is installed on COM15. Matching LittleFS was installed and
  hash-verified after Jon explicitly requested overwrite with no backup. No backup
  was taken; credentials and the two client records remain in NVS. No factory
  reset, credential rotation, firewall change or live external BBS call was needed.

Bench findings fixed during implementation: a command can start after its caller's
loop timestamp; UART driver/ring writes can block during an RTS pause. Host output
now uses nonblocking FIFO writes, with deadlines and signal restoration. The PC
peer separates protocol output from lrzsz's exit-time PTY flush and retains frame
boundaries across socket read timeouts. Logs never include credentials or payload.
