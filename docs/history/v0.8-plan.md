factory default at 14.4k, and add `AT*MODEL=` to select one of these series:

| Selected model | Default CONNECT speed to report |
|---|---|
| Sportster 14.4k Series (factory default) | 14400 |
| Sportster 28.8k Series | 28800 |
| Sportster 33.6k Series | 33600 |
| Sportster 56k Series | 56000 |

  Keep identification/reporting defaults separate from operational settings.

## Confirmed command, persistence and reporting rules

Jon answered all four model questions on 25 Oct 2026:

1. The selected model is **device-wide and saved immediately**. `AT&W` is not
   needed to save it. `AT&F` and `ATZ` retain it; `AT*FACTORY` restores the
   **Sportster 14.4k Series** selection.
2. An explicit phonebook speed or `&N` setting takes precedence over the model's
   default CONNECT speed. The model supplies the fallback. Example: select the
   56k model, then explicitly set `AT&N8`: CONNECT reports **14400**.
3. The project command is exactly **`AT*MODEL`** (AT, star, MODEL), not a standard
   Hayes `ATMODEL` command. Assignment accepts **14400, 28800, 33600, 56000**:
   `AT*MODEL=14400`, `AT*MODEL=28800`, `AT*MODEL=33600`, `AT*MODEL=56000`.
   Include the query/list companions discussed with the command: `AT*MODEL?`
   shows the current model and `AT*MODEL=?` lists the choices.
4. A changed model's CONNECT default applies to the **next call**. The current
   call retains its original reported speed, including subsequent `ATO` replies.
   Save the selected model immediately without rewriting the active call's data.

Implementation must distinguish model fallback from a user-selected speed. The
current factory `&N8` uses the same stored value as an explicitly selected 14400
speed, so that value alone cannot distinguish intent. Add appropriate metadata
and specify migration/reset behavior before changing storage; preserve saved
explicit speeds and do not repurpose `&N0` (highest speed) as a model-default flag.
Test the agreed rules across saves, restarts, factory profiles and active calls.

## Password echo correction (v0.8)

- Fix the reported `AT*PASS=` echo bug: show the command and the separator `=`;
  mask only characters after that separator. Example: `AT*PASS=********` for an
  eight-character password. An `=` inside the password remains masked.
- Inspection confirms that `Port::feed()` marks the line private as soon as PASS
  is recognized, so the following separator is currently echoed as `*`. Separate
  the echo boundary from the command's sensitive classification; retain masking,
  buffer wiping, log exclusion and the `A/` repeat prohibition.
- Add regression coverage for exact echo, case-insensitive input, secret values
  containing `=`, backspace/DEL across the separator, echo off, command prefixes,
  overflow and failed validation. Extend serial acceptance without exposing test
  credentials in failure output. No password or credential changes are needed
  merely to update this plan.

## Implementation scope

Model-selection logic, persistence and AT command handling follow the confirmed
rules above, with hardware-independent logic in `lib/`. Password echo correction is
independent. The outgoing-call implementation covers:

1. Add hardware-independent phonebook logic and its versioned, CRC-protected NVS
   store. Preload entry `1` with `www.amigaretro.com:23`, by hostname. Preserve exact
   numeric keys, reserved-number exclusions, Telnet/raw mode and optional speed.
   Keep the four `&Z` numbers separate, implement `ATDSn`, retain phonebook through
   `AT&F`/`ATZ`, and include it in recoverable `AT*FACTORY` erasure. Register every
   management command in the shared `AT*` table and help.
2. Add an asynchronous outgoing-call state machine in `lib/`, with DNS/TCP in
   `lib/hw`. Validate before sounds, claim the shared call slot while dialling,
   support `ATD`/`ATDT`/`ATDP`, stored numbers, last-dialled tracking and repeat.
   Bound connection attempts using S7; handle cancellation and clean up on every
   exit. Keep the other local port and the Wi-Fi service responsive.
3. Adapt Zimodem Telnet code with attribution and change notices. Support BINARY
   in both directions, terminal ANSI, window 80x24 and IAC escaping. Raw TCP passes
   bytes unchanged. Preserve backpressure and bounded buffering, including while
   escaped to online command mode. Remote bytes never enter the local AT parser.
4. Integrate `+++`, `ATO`, `ATH`, resets, DTR, flow control, DCD and activity LEDs.
   Apply per-entry speed or `&N`, then implement outgoing `&B0`/`&B2` speed following
   and optional line-speed throttling (default off). The console stays at 115200.
5. Source and verify freely licensed handshake recordings before adding them;
   record provenance, licence and conversions in `credits/LICENSES.md`. Validate
   8 kHz mono, 16-bit PCM WAVs and play them from LittleFS. Keep dial tone -> actual
   dialled DTMF/pulse digits -> handshake -> CONNECT, without ringback. Replace
   blocking call playback with a service that permits cancellation and serial,
   Wi-Fi and pot updates. Support `ATM0/1/2` and `ATL0-3`, amp shutdown when idle,
   and apply the -7 dB cap last. `ATM0` skips the sound delays.
6. Map refusal to BUSY, connection timeout to NO ANSWER, DNS/no Wi-Fi to
   NO DIAL TONE, and remote/Wi-Fi loss after connection to NO CARRIER. Apply the
   existing V/Q/X result filtering and prevent duplicate final results.

Confirmed implementation choices: 64 phonebook entries, the approved
`AT*PHONEBOOK?` / `AT*PHONEBOOK=` / `AT*PHONEDELETE=` syntax, and saved device-wide
`AT*THROTTLE=ON|OFF`, default OFF. Intermediate rates use the nearest lower of the
six sound rates (1200 for 300). Jon approved the licensed generic recording as an
explicit fallback for five missing speed-specific recordings; only the 1200 asset
has a verified speed-specific source. Originals and conversions are credited in
`credits/LICENSES.md` and reproduced by `scripts/build_handshakes.py`.

## Implementation and acceptance record (25 Oct 2026)

The v0.8 implementation is committed in draft PR #10. Native checks: 263 pass.
On-board: 29 unique checks pass, including scratch model/phonebook NVS, all six
LittleFS WAVs, nonblocking I2S/ADC, and held-off RTS drain/shutdown. Console regression:
68 pass, 27 skip for unwired/opt-in cases. All ten outgoing-call checks pass: RAW
binary transfer, fragmented Telnet, true TCP refusal, DNS failure, deadline/cancel,
Wi-Fi loss, model persistence/stable ATO reporting, streamed audio and live ATDT1.
Formatting and cppcheck pass; CI results are attached to the PR.

The refused-connection check found that lwIP reports an active rejection during
connect as ECONNRESET (104), in addition to ECONNREFUSED (111). Both now map to
BUSY while connecting; established-call resets remain NO CARRIER. The Windows test
server uses SO_CONDITIONAL_ACCEPT/WSAAccept to reject requests through the existing
Python rule. `scripts/test_refusal.ps1` no longer needs Administrator access or
changes firewall rules. The temporary rule from the earlier probe is absent.

Remaining hardware acceptance: external RS232 and listening require the missing
level shifters/DB9 and amp/speaker. No model, audio-source or software-acceptance
questions remain. Shared structure changes required a clean firmware rebuild to
eliminate stale-object heap corruption seen during the bench run. Final validation
uses a clean build; temporary heap/audio/TCP traces were removed. UART speed changes
use bounded drains. Call tests explicitly establish model/throttle defaults because
AT&F correctly preserves these device-wide settings.
