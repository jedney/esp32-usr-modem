Implementation plan requested by Jon on 27 October 2026. Based on `CLAUDE.md`,
`docs/ROADMAP.md`, project brief 6.1-6.6 (Q12, Q13, Q30, Q42 and Q51), the
decisions log, the v0.12 code and tests, and the upstream sources below.
Jon requested implementation after planning. Implementation and available-bench
acceptance are complete on `firmware/v0.13-internet-dialup`; verification is below.

## Required behavior and bench

- PPP: `ATDT666` and Zimodem alias `5517546`. SLIP: `ATDT667` and alias
  `5517545`. Retain the existing classifier, dial modifiers and reserved-number
  protection in the phonebook. Route these numbers locally, never to DNS/TCP.
- Default IPv4 network: `10.64.64.0/30`, modem `10.64.64.1`, client
  `10.64.64.2`. Addresses are configurable. Translate client traffic to the
  modem's Wi-Fi station address, with working return traffic, DNS and TCP browsing.
- Any PPP username/password is accepted. These are unrelated to the device
  password and are never stored, logged, echoed or exported.
- DTR hang-up and PPP LCP termination release the session without a reboot.
  Restore command mode, UART/flow settings, call ownership and normal services.
  Preserve existing `&D` and `&C` semantics; verify ordinary hang-up with `&D2&C1`.
- Console COM15 at 115200; Unitek RS232 COM18. All hardware components are wired,
  as reconfirmed by Jon. This does not establish physical acceptance.
- Jon confirms neither a Windows 9x machine nor an Amiga TCP stack is available
  and defers legacy-client acceptance (27 October). Proceed with automated PC
  protocol/NAT and COM15/COM18 bench validation. Real legacy-client browsing
  remains outstanding against the roadmap's final acceptance criterion.

## Architecture and first feasibility gate

Use a portable Zimodem-derived PPP/SLIP engine in a new `lib/internet/`, with
network-interface, routing and NAT access behind `lib/hw`. Prefer the existing
ESP-IDF 4.4 lwIP NAPT implementation over a new hand-written NAT. Keep Arduino
core 2.0.17, the confirmed pins, partition map and existing application behavior.

Before implementing the whole feature:

1. Establish a reproducible S3 SDK/library build compatible with the installed
   core, starting from Espressif's lib-builder `release/v4.4` and the exact
   matching IDF sources. Pin immutable revisions, configuration and artifact
   hashes. Enable IPv4 forwarding, NAPT and its required L2-to-L3 copy support.
   An application `-D` cannot enable code absent from precompiled libraries.
2. Integrate the resulting framework package through project configuration,
   including OTA, clean installs and CI. Do not patch Jon's shared PlatformIO
   installation or depend on an unrecorded local binary replacement. Preserve
   ABI/configuration agreement between SDK headers and every rebuilt library.
3. Prove a private serial network interface can send and receive translated
   UDP/TCP/ICMP traffic through Wi-Fi, while the modem's HTTP status, DNS/NTP and
   ordinary local sockets still work. Verify routing and pbuf ownership on the
   lwIP TCP/IP task; keep Wi-Fi as the upstream/default route.
4. Prove repeated creation/removal, NAT cleanup, Wi-Fi disconnect/IP change and
   reconnect work without stale callbacks, memory growth or reboots. Capture
   resource use and confirm the app still fits its 4 MiB OTA slot.

The gate passes only with a repeatable build plus bidirectional wired traffic
and teardown evidence. If a compatible SDK cannot be produced, document the
specific failure and revise the transport/NAT design before proceeding. Do not
silently migrate to core 3.x or substitute Zimodem's shared-IP forwarding.

The retrieved Zimodem source supplies useful framing and integration ideas,
but is not a complete implementation of this project's requirements. Its
receive hook diverts IPv4 traffic addressed to the modem itself, and its PPP
IPCP implementation assigns the Wi-Fi address. Replace that routing model.
Review negotiation independently: upstream acknowledges options indiscriminately,
changes IPCP request contents inside ACKs, and has incorrect LCP echo code
constants. Port attribution and useful code, rather than those behaviors.

## Implementation sequence

### 1. Portable framing and PPP negotiation

- Separate bounded PPP/SLIP codecs, PPP control state, settings and call lifecycle
  from Arduino/lwIP. Inject time, packet I/O and storage. Keep all serial work
  incremental, with fixed bounds for frames, queues, options, retries and timeouts.
- Adapt PPP asynchronous framing/FCS from the pinned Zimodem source, verified
  against independent RFC vectors. Handle fragmented input, escaped control bytes,
  ACCM, malformed/truncated frames and resynchronization after overflow.
- Implement both sides of LCP/IPCP configuration: exact ACK matching, NAK/reject
  handling, request IDs, duplicates, retransmissions, restart/termination and echo.
  Negotiate MRU and compression options only when implemented. Reject unsupported
  compression/encryption/network protocols predictably; do not pretend support.
- Support unauthenticated PPP and PAP with any bounded, well-formed credentials.
  Configure legacy clients accordingly. If the selected acceptance client needs
  CHAP, add and independently test that mode before claiming its compatibility.
  Never reuse the modem's device credential or retain authentication payloads.
- IPCP assigns the configured client/local addresses and offers usable upstream
  DNS through its DNS options. Gate IP forwarding on completed negotiation.
  Use proper NAK suggestions when a client initially requests zero/wrong addresses.
- SLIP implements END/ESC framing, leading/empty delimiters and recovery from
  invalid escapes/oversized frames. It has no login, address negotiation or LCP;
  document the client's static address, peer, route and DNS setup. Do not assume
  CSLIP/Van Jacobson compression support.

### 2. Network adapter and NAT

- Attach a dedicated serial IPv4 netif with the configured /30 addresses and
  bounded packet queues. Marshal netif/NAT operations to the TCP/IP task. Network
  callbacks enqueue packets and never block on UART output or call menu/AT code.
- Enable NAPT on the serial ingress interface, preserve station routing and
  avoid the upstream blanket Wi-Fi input hook. Validate source address, IPv4
  lengths/checksum and MTU; handle chained pbufs and every success/failure ownership
  path correctly. State the supported TCP, UDP and ICMP behavior explicitly.
- Test translation checksums, multiple simultaneous flows, port collisions with
  local sockets, mapping exhaustion/expiry, TCP close/reset and ICMP errors.
  Verify MTU/fragmentation/DF behavior and large TCP responses; a small ping alone
  is insufficient evidence for browsing. Define bounded rejection for unsupported
  packet forms without corrupting other traffic.
- On hang-up, remove routes/interface, disable and clear this session's NAT state,
  cancel queued work and invalidate late callbacks using a session generation.
  Resolve the mapping cleanup API during the first gate, not after integration.
- A Wi-Fi loss or station IP/subnet change terminates the call and cleans up.
  A new call uses the new upstream address/DNS. Never transparently keep stale NAT.

### 3. Dial lifecycle and binary serial transport

- Route special numbers through an Internet dialer, retaining the dial/pulse,
  handshake, model/explicit CONNECT speed, `&N`/`&U`, optional throttling and
  speaker-volume behavior. `ATM0` connects without a silent handshake delay.
- Claim the slot before starting work. Busy ownership gives BUSY; unavailable
  Wi-Fi gives NO DIALTONE. Define bounded setup/PPP negotiation failure results
  and emit exactly one terminal result. CONNECT precedes PPP/SLIP bytes; IP-ready
  status is separate from the initial serial carrier connection.
- Support directly attached console and RS232 calls. Reuse browser/menu departure
  semantics: browser dialing hands the call to RS232 rather than carrying packets
  through the browser terminal. Incoming network callers cannot start these services.
- During binary mode suppress online echo, unsolicited text, menu redraws, software
  flow control and `+++` interpretation without changing the saved modem profile.
  Retain configured hardware RTS/CTS. Test all 256 values, including XON/XOFF,
  `+++`, CR/LF, ESC and command-looking payloads.
- End PPP on peer LCP Terminate-Request after the bounded Terminate-Ack drain.
  DTR follows `&D`/S25; DCD follows `&C`. SLIP hang-up uses DTR on RS232 and a
  local management hang-up command. Add management hang-up for console calls,
  whose USB control lines are reserved for ESP reset/boot and are not host DTR.
- Proposed command grammar: `AT*INTERNET?` for configuration/live state;
  `AT*INTERNET=IP,<modem>,<client>` for the /30 pair;
  `AT*INTERNET=DNS,AUTO|<IPv4>` for DNS policy; and
  `AT*INTERNET=HANGUP` from a local management session. The active binary owner
  never parses these bytes. Other-port management must work while the slot is busy;
  browser hang-up follows the existing authenticated call-control access policy.
  Check command registry capacity and parsing limits before adding entries.
- Every completion/failure/cancellation path restores UART speed/flow, carrier,
  audio, queues and ownership. Exercise ATH/Z after returning to command mode,
  DTR during setup/traffic, negotiation timeout, Wi-Fi failure, stalled RTS and
  immediate redial. Keep watchdog, clock and web status serviced throughout.

### 4. Settings, UI, status and history

- Store checked/versioned Internet settings with absent/corrupt-record defaults
  and failed-save rollback. Validate a usable private /30 pair, reject equal,
  network/broadcast or Wi-Fi-overlapping addresses, and recheck overlap on dial.
  Reject changes during a call; apply changes to the next call.
- Include Internet settings in factory reset and secret-free export/restore.
  `&F`/`Z` retain these device-wide network settings like existing Wi-Fi settings.
- Add Internet configuration/help to the shared serial/browser menu, with every
  action backed by AT*. Preserve 80x25, plain/CP437, model themes and browser layout;
  update UI definition/bindings, generated artifacts and parity/layout tests together.
- Publish PPP negotiating/ready or SLIP state, selected addresses/DNS, duration,
  byte/packet/drop counters and last termination reason. Use existing web `ppp`/
  `slip` states; document any additional fields in `web/PROTOCOL.md`.
- Extend call journal/history with an explicit call kind and compatibility for old
  raw/Telnet records. Record one completion per call; no credentials or packets in
  debug logs/history. Update About/credits from the licensing record.

- Matching esp_littlefs/littlefs sources are pinned to Arduino's recorded SDK

  passes with no medium/high findings. Firmware builds within its 4 MiB OTA slot.
- All three new on-board checks pass: real CPU/flash/PSRAM configuration, 20 real
  netif/NAPT create/remove cycles with bounded heap use, and scratch-NVS roundtrip.
  The first PSRAM assertion was corrected: Arduino reports allocatable PSRAM

- Normal v0.13 firmware is restored with the native-test upload gate intact.
  LittleFS was retained; no filesystem replacement or credential change was needed.
- Initial wired negotiation exposed stale loop timestamps causing immediate
  unsigned timeout, and capture transitions around CONNECT/DCD. The engine rejects
  stale ticks; serial hooks end capture before CONNECT and restore it before DCD

  made Ethernet output reject them. Real round trips verify the corrected path.
  PL2303 manual RTS tests disable its automatic RTS mode before holding the line.
- NAPT ports 32768-49151 are separate from the modem's local ephemeral ports;
  CMake applies these definitions to lwIP and application code. Ingress source,
  length/checksum and fragmentation bounds are enforced. Fragmented IPv4, IPv6,
  CSLIP and packet compression remain unsupported. Local firmware PING is refused
  during Internet calls to avoid ambiguous ICMP identifiers; client ping works.
- New Internet E2E suite: **11 passed, two optional PC UDP echo skips**. PPP and
  SLIP both pass full binary ICMP and UDP DNS through Wi-Fi NAPT, RTS pause/resume,
  all four numbers, LCP/DTR hang-up, console/RS232 management, timeout, settings
  reboot/export and Wi-Fi loss/redial. PC UDP echo requires a new port allowance;
  no firewall rule was changed. Existing allowed TCP 32321 supports HTTP tests.
- Full regression: **155 passed, nine skipped in 744.80 seconds**. Skips are
  explicit optional device/reset/upload/live-call cases plus the two PC UDP tests.
  RS232 300-115200, existing calls, Client Tests, configuration, hardware, web and

  tests pass again after the network changes; normal firmware is then restored.
