until v0.12. Retain ANSI, CP437 and plain terminal styles.

`AT*MODEL?` reads the saved active identity;
`AT*MODEL=14400|28800|33600|56000` saves it device-wide immediately, rolling back
on save failure. It changes identity and the next call's default reported speed;
explicit entry/profile speeds take precedence and the current call remains stable.
Read this state directly for rendering, rather than issuing AT queries on redraw.
`modemcfg::modelName()` currently labels every unrecognized value as 14.4k: use
explicit validation for the UI's unknown state and test it.

The Phonebook's existing factory BBS entry is real product behaviour. Preserve it;
do not replace stored data or add the fictional contacts shown in the wide image.
Speed zero means no entry override, not an observed connection rate. Stored
credentials, notes, init strings and compression information do not exist in this
record and must not be invented.

## Implementation sequence

### 1. Patch-version support and production catalogue

- Extend `scripts/bump_version.py` with a patch increment; retain existing
  major/minor behaviour and accept an optional patch in input. Bump once to 0.11.1
  during implementation and write an appropriate Added / Changed / Fixed entry.
- Update `scripts/version.py`, `scripts/check_version.py`,
  `web/src/upload.js`, and `lib/webinterface/src/web_policy.cpp` together.
  Check image markers, manifests and the release workflow for three-part handling.
  Compare numeric tuples, treating an omitted patch as zero: 0.11 < 0.11.1 < 0.12;
  preserve rejection of malformed, overflowing or conflicting identities.
- Account for an existing v0.11 browser rejecting a 0.11.1 image before upload.
  Document a tested initial USB or existing ArduinoOTA upgrade path, then verify
  browser upload on the upgraded firmware. Do not weaken image validation to
  disguise the new version as 0.11.
- Generate a small C++ catalogue/theme header from the JSON using Python's standard
  library. Give each item a stable ID, label, hotkey, summary and declared state.
  Bind IDs to existing commands/targets and their input/secret/leave/RS232 rules.
  Fail generation/tests on missing or duplicate bindings. Do not parse JSON on the
  ESP32 or require the design package to be served by HTTP.
- Integrate generation with native and device builds, following the existing
  generated-credits pattern. Test deterministic output and stale-file detection.

### 2. Geometry, capabilities and bounded cell rendering

- Add a portable layout/cell writer under `lib/config/src/`, independent of Arduino.
  Track columns/rows, colour capability and character encoding per terminal.
  Keep user text separate from trusted rendering escape sequences.
- Use the supplied five-row red wordmark and exact compact grid for Main; use the
  one-line red brand for children, fixed frames, cyan titles, green keys, blue
  working F-key hints, feedback, actual state and `Command >` focus indication.
- Compact applies at 80x25 and intermediate widths. Use enhanced rendering only at
  >=120 columns with enough rows, initially >=45; use all available space within
  bounded limits at 120x45 and 132x50. At short/narrow dimensions use a minimal
  paged layout with an explicit size notice and reachable controls.
- Provide ASCII-safe ANSI, CP437 line/block glyphs, browser Unicode conversion and
  a plain transcript fallback. Plain mode stays usable without cursor controls;
  the framed, positioned 25-row design applies to cursor-capable terminals.
  Use exact RGB in the browser, with ANSI approximations on restricted clients.
- Measure cells after decoding text, not UTF-8 bytes. Prefer a fixed single-cell
  glyph repertoire and sanitize unsupported user glyphs; test combining and wide
  input so it cannot displace frames. Preserve control-sequence sanitization.
- Draw by cursor position without a trailing newline at the lower-right cell;
  account for delayed wrap and restore cursor/attributes/wrap state on every exit.
  Keep response/export paging separate: export bytes must remain replayable.
- Retain bounded chunked output and backpressure. A wide coloured frame can exceed
  the present 32 KiB terminal buffer and 16 KiB browser output queue: stream rows
  or bounded redraw segments, coalesce resize/redraw requests, and do not truncate
  a frame or disconnect a healthy client merely because it needs a large redraw.
- Serial ports have no current geometry negotiation. Default to 80x25; support
  bounded terminal size reports where available with a timeout/fallback. Supply
  an explicit per-session dimension override for clients that cannot report size,
  with shared-menu/AT* parity and help. Keep this limited to UI geometry; the v0.12
  client diagnostic suite remains out of scope.
- Resize the adaptive browser's xterm from measured available cells and
  deliver bounded/coalesced dimensions to the owner through an explicitly
  documented addition to the existing authenticated WebSocket protocol. Queue
  geometry across the current server/modem-task boundary; callbacks must not
  mutate the terminal. Keep 80x25 as the compatibility default. Validate limits,
  prevent observer resizing of another session, and preserve binary key framing.

### 3. Keyboard, focus and navigation state

- Add an incremental decoder for CSI/SS3 arrow, Home/End, PgUp/PgDn and supported
  F-key sequences, including fragmented input. Distinguish bare Esc using a short
  bounded timeout. Ignore malformed/overlong sequences safely.
- Use states for menus, list selection, text entry, confirmation, async operation,
  details and command results. Menu hotkeys act only in menu focus; forms accept
  printable keys, editing, cursor movement, Tab and safe cancellation.
- Match JSON keys exactly. Root Up/Down follows enabled rows in its column;
  Left/Right chooses the nearest enabled row in the other column. Enter activates
  selection, D reports Client Tests unavailable, and disabled entries are skipped.
- Esc/Q goes Back in menus; Q/F10 exits from Main using existing ownership cleanup.
  Preserve Ctrl-C emergency exit and guarded +++/ATO behaviour. In forms, Q is text
  and Esc cancels safely. Implement contextual F1 help and advertise only controls
  actually handled in the current transport/context.
- Store selected stable ID and page/scroll offset per screen on a Back stack.
  Returning from Profile must restore Settings, rather than jumping to Main.
  Preserve selection on refresh/model change/resize; clamp it after deletion.
- Update automation for the deliberate root-key/Q/Back changes. Handle CRLF and
  trailing Enter from a hotkey-plus-Enter client so they cannot submit an empty
  form, confirm an action or execute a second choice accidentally.

### 4. Real state, Phonebook and command results

- Expose read-only snapshots for model, active profile values, link/call state,
  host baud, network/clock and available hardware flags. Reuse existing objects
  in `src/main.cpp`; show Unknown/-- when the requested value has no source.
  Do not label an active modified profile as a known stored profile without proof.
- Refresh state without resetting focus or overwriting edits. A model change uses
  all four exact subtitles/accents; nominal model identity never becomes live rate.
- Give the terminal structured access to the existing Phonebook through a narrow
  service interface. Keep number as the stable selection key, even if the store
  compacts after delete. Distinguish no entries, not loaded and service failure.
- Compact Phonebook: nine entries per page in rows 7-15, summary, four actions,
  I/Enter details, paging and disabled Delete/Dial without a selection. Use the
  saved host as NAME as confirmed by Jon; show the full host, port,
  protocol, number and configured speed in Details.
- Wide Phonebook: selectable table at left; four command cards and selected-entry
  details at right. Use actual values and fitting cell art, not the PNG itself.
- Dispatch writes through the current validation/storage/command services. Recheck
  the selected entry before delete/dial, handle save failure, and confirm both.
  Serial dial retains its existing departure flow; browser dial continues to
  target the idle RS232 host and returns the browser to read-only live status.
- Frame/page the existing Status, Call History, Export, Reference and About output.
  Keep existing asynchronous prompts, test cancellation and result reporting.
  Every unsupported action remains reachable with the missing hook named; do not
  claim a missing data field makes an otherwise supported service unavailable.

### 5. Action safety and enhanced presentation

- Audit each of the 57 bindings for capabilities, validation, confirmation,
  cancellation and actual completion. Add confirmation for delete, dial, clear
  logs and consequential profile/network/device changes where it is missing.
  Reuse existing factory/restart confirmation rather than stacking prompts.
- Block duplicate activation while busy. A cancelled/failed operation cannot show
  success. Clear secret input and pending commands on cancel/exit/disconnect;
  preserve browser write-only password handling and network rollback.
- Preserve one owner across console/RS232/browser, read-only observers, Q79 hardware
  restrictions, remote-caller isolation, resource restoration and audio limits.
- Build the wide Main with two columns of framed cards/descriptions, red branding
  and fitting mirrored modem cell art. Preserve every option and the real footer;
  omit fictitious COM/IRQ/serial/compression/date values from the concept images.
- Refresh the labelled browser DEMO from the same catalogue/theme data or generated
  fixtures so it has the new inventory and disabled v0.12 item. It must remain
  visibly synthetic and must never write contacts or settings to the modem.
