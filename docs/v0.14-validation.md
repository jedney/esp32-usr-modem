# v0.14 pre-v1 correctness fixes

Scope: the seven findings in [the pre-v1 review](v1-code-review.md), without the
optional resource refactors or an SDK migration. Bench: console COM15, RS232
COM18, all components wired. Filesystem contents and production credentials are
retained.

## Changes

- R1: both serial adapters use the same bounded 512-byte pending-input buffer.
  A partial `Session::fromHost` result retains its tail for the next poll, including
  command-to-service transitions. Consumed input copies are wiped.
- R2: network controllers ignore stale ticks and browser changes establish their
  clock baseline before reconnecting. The loop supplies a fresh network timestamp.
- R3: the Wi-Fi operation is reserved from password-prompt entry through join
  completion. Cancellation, invalid input, two-minute prompt expiry and browser
  disconnect release the reservation; another port cannot replace the SSID.
- R4: playback and downloads share the six packaged sound records. ALL includes
  HS56000.WAV. HS9600.WAV is a compatibility alias of HS2400.WAV, consistent with
  existing playback; no new recording is claimed.
- R5: LCP/IPCP renegotiation starts a fresh 30-second deadline and retry budget;
  both reconnection and timeout remain tested.
- R6: network setters persist a candidate before radio/live changes, with explicit
  browser transaction deferral. Modem NVRAM setters restore rejected mutations.
  Later successful saves cannot persist a rejected change.
- R7: NVS reads return an explicit nonempty error for oversized, wrong-type or
  unreadable records, rather than treating them as absent. Authentication and web
  settings fail validation; credentials are not silently replaced.

## Validation

Local logs are in the ignored `.pio/review-v14-*` files.

- Native: 385 passed, including the review failure-path regressions.
- Browser: 22 passed.
- Script/layout: 18 passed, seven subtests passed.
- cppcheck: passed with zero high/medium defects; low-severity notices remain.
- clang-format, version/changelog and generated-UI consistency: passed.
- On-board: 44 passed, nine skipped across 11 compiled programs. The skips are
  the internal RS232 tests that require the receivers to be absent; the actual
  wired COM18 suite passes instead. The new real-NVS and sound-source checks pass.
- End-to-end: 158 unique passed, nine optional skips across resumed batches.
  Covers COM15/COM18 at 300-115200 baud, the 1,600-request PPP reply-pressure
  regression, late PPP renegotiation, cross-port password prompts, Wi-Fi/NTP,
  incoming/outgoing calls, remote isolation and authenticated browser behavior.
- Independent portable pppd/kernel: binary UDP and LCP termination passed.
- Independent lrzsz over COM18: all ten standalone X/Y/ZMODEM upload/download
  cases passed with zero retries/errors. Both full ALL batches passed: seven
  files, 1,442,603 bytes, CRC32 D4B25277; YMODEM took 210.4 s and ZMODEM 266.2 s.
  Every received WAV matched its packaged bytes; aggregate counts/CRC include
  the frozen log. Host baud and active profile were restored afterwards.
- Independent wired pppd 2.4.9: verified 65,536 HTTP bytes plus two concurrent
  8,192-byte flows, DNS, real Wi-Fi NAT source/port isolation, authenticated local
  HTTP during PPP, and LCP hang-up passed.
- Firmware and LittleFS image builds plus image-manifest validation: passed; the
  filesystem image was built locally without installing it.
- Release build: passed, 1,224,057 bytes flash and 140,544 bytes static RAM.
  The serial buffers add about 1 KiB static RAM; all feature and queue limits remain.

Embedded tests use scratch settings/files for destructive cases and were followed
by normal v0.14 firmware restoration through the native-test gate. No production
factory reset, device-password rotation or filesystem replacement is part of this
validation.

The initial Windows LAN socket block was resolved by Jon restoring session network
access; all previously blocked cases were rerun. The pressure test load was raised
to 1,600 requests to exceed the real 8 KiB UART buffer and verify CTS deassertion
before resuming RTS.

## Remaining acceptance

Real Amiga/Windows 9x compatibility and physical panel/listening/enclosure sign-off
remain as previously recorded. ESP-IDF 4.4 maintenance status and the agreed HTTP/
unencrypted-NVS trust model are unchanged. The optional memory/CPU simplifications
in the review remain separate work.
