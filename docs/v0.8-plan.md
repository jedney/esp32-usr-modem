# v0.8: outgoing calls

Plan updated 25 Oct 2026. One branch: `firmware/v0.8-outgoing-calls`, based on
the merged v0.7. VERSION is bumped once to 0.8; further work on this branch uses it.

## Confirmed model-selection requirement

Jon's latest request supersedes the fixed 14400 identity requirement. Keep the
factory default at 14.4k, and add `AT*MODEL=` to select one of these series:

| Selected model | Default CONNECT speed to report |
|---|---|
| Sportster 14.4k Series (factory default) | 14400 |
| Sportster 28.8k Series | 28800 |
| Sportster 33.6k Series | 33600 |
| Sportster 56k Series | 56000 |

- Model selection affects only the model's ATI identification and the default
  speed reported by CONNECT. It must not restrict commands, speed choices or
  other features. Apply the existing verbose/numeric/quiet/X result formatting.
- Keep all selectable line speeds through 56000, existing USR V.90 `&N`/`&U`
  indexes through 38, and `&N0`'s highest-speed meaning. Host serial remains
  300-115200; the maintenance console stays at 115200.
- Do not implement model changes by rewriting an explicit `&N`, a phonebook
  entry, serial baud, flow-control policy, handshake playback or throttling.
  Keep identification/reporting defaults separate from operational settings.
- Add the command to `AT*HELP`, document model labels and command values, and
  document each model's ATI responses. Research real identity data; mark unverified
  fields as emulator placeholders rather than attributing the old 33.6 ROM capture
  to every series. Settings inquiries must continue showing the actual settings.
- Add a model selector to the future `AT*CONFIG` menu (v0.10); the web interface
  (v0.11) exposes the same setting through the shared configuration menu.
- Show the selected model prominently on the first configuration page in both
  interfaces. Consider ASCII art of the selected modem above the menu. ASCII art
  is an option, not a required deliverable; keep it readable in plain/ANSI/CP437
  modes and within the existing terminal dimensions.

The existing branch implements a fixed 14400 identity, factory `&N8`, and extended
speed tables exercised with `AT*TESTCALL`. Configurable models and the reporting
rules above are planned, not implemented. Neither this preparation nor the plan
completes outgoing calls or the v0.8 roadmap acceptance.

## Model details awaiting Jon's answers

1. Persistence/reset scope: a device-wide selection saved immediately, retained
   by `AT&F`/`ATZ`, reset to 14.4k by `AT*FACTORY` (recommended), or a per-profile
   setting saved by `AT&W` and restored with that profile?
2. Speed precedence: should an explicit phonebook speed or `&N` override the
   model's default CONNECT speed (recommended)? Example: 56k model with explicit
   `&N8` would report CONNECT 14400. The alternative is that the model always
   controls the reported speed. Do not assume either rule.
3. Command values: numeric rates `14400|28800|33600|56000` (recommended), or labels
   `14.4k|28.8k|33.6k|56k`? Proposed companions: `AT*MODEL?` for the current model
   and `AT*MODEL=?` to list choices.
4. Changes during a call: apply the new default to the next call, keeping the
   current call's reported speed and ATO response stable (recommended), or use
   the new model for the current call's next ATO response as well?

Once precedence and persistence are settled, explicitly specify how to distinguish
a model default from a user-selected speed. The current factory `&N8` uses the same
stored value as an explicitly selected 14400 speed; it cannot distinguish intent.
Document migration of existing profiles and reset behavior before changing storage.
Use the answer about active calls to specify when the reporting default is sampled;
keep that behavior separate from the call's operational settings.

## Password echo correction (v0.8)

- Fix the reported `AT*PASS=` echo bug: show the command and the separator `=`;
  mask only characters after that separator. Example: `AT*PASS=********` for an
  eight-character password. An `=` inside the password remains masked.
- Inspection confirms that `Port::feed()` marks the line private as soon as PASS
  is recognized, so the following separator is currently echoed as `*`. Separate
  the echo boundary from the command's sensitive classification; retain masking,
  buffer wiping, log exclusion and the `A/` repeat prohibition.
- Add regression coverage for exact echo, case-insensitive input, secret values
  containing `=`, backspace/DEL across the separator, echo off, command prefixes,
  overflow and failed validation. Extend serial acceptance without exposing test
  credentials in failure output. No password or credential changes are needed
  merely to update this plan.

## Remaining implementation

Add model-selection logic, persistence and AT command handling after the questions
above are answered; keep hardware-independent logic in `lib/`. Add the password
echo correction independently. The remaining outgoing-call work is:

1. Add hardware-independent phonebook logic and its versioned, CRC-protected NVS
   store. Preload entry `1` with `www.amigaretro.com:23`, by hostname. Preserve exact
   numeric keys, reserved-number exclusions, Telnet/raw mode and optional speed.
   Keep the four `&Z` numbers separate, implement `ATDSn`, retain phonebook through
   `AT&F`/`ATZ`, and include it in recoverable `AT*FACTORY` erasure. Register every
   management command in the shared `AT*` table and help.
2. Add an asynchronous outgoing-call state machine in `lib/`, with DNS/TCP in
   `lib/hw`. Validate before sounds, claim the shared call slot while dialling,
   support `ATD`/`ATDT`/`ATDP`, stored numbers, last-dialled tracking and repeat.
   Bound connection attempts using S7; handle cancellation and clean up on every
   exit. Keep the other local port and the Wi-Fi service responsive.
3. Adapt Zimodem Telnet code with attribution and change notices. Support BINARY
   in both directions, terminal ANSI, window 80x24 and IAC escaping. Raw TCP passes
   bytes unchanged. Preserve backpressure and bounded buffering, including while
   escaped to online command mode. Remote bytes never enter the local AT parser.
4. Integrate `+++`, `ATO`, `ATH`, resets, DTR, flow control, DCD and activity LEDs.
   Apply per-entry speed or `&N`, then implement outgoing `&B0`/`&B2` speed following
   and optional line-speed throttling (default off). The console stays at 115200.
5. Source and verify freely licensed handshake recordings before adding them;
   record provenance, licence and conversions in `credits/LICENSES.md`. Validate
   8 kHz mono, 16-bit PCM WAVs and play them from LittleFS. Keep dial tone -> actual
   dialled DTMF/pulse digits -> handshake -> CONNECT, without ringback. Replace
   blocking call playback with a service that permits cancellation and serial,
   Wi-Fi and pot updates. Support `ATM0/1/2` and `ATL0-3`, amp shutdown when idle,
   and apply the -7 dB cap last. `ATM0` skips the sound delays.
6. Map refusal to BUSY, connection timeout to NO ANSWER, DNS/no Wi-Fi to
   NO DIAL TONE, and remote/Wi-Fi loss after connection to NO CARRIER. Apply the
   existing V/Q/X result filtering and prevent duplicate final results.

Implementation choices still to document: phonebook capacity/management syntax,
throttling command and handshake-file mapping for intermediate rates. Proposed
defaults should be reviewed before depending on them; licensed source availability
also determines which genuine recordings can be bundled.

## Validation and bench limits

- Native: phonebook validation/storage, state transitions, cancellation/deadlines,
  Telnet fragmentation/escaping, flow control/backpressure, speed selection,
  WAV validation and volume. Add meaningful tests before deployment.
- Models: test all four ATI identities and reporting defaults, explicit speed
  precedence, unchanged speed/command support under every model, storage/migration
  and reset semantics once agreed, and no changes to operational call behavior.
- Password echo: exact visible separator and masked value, no leaked bytes during
  editing/failures, unchanged secret handling, and console regression coverage.
- Future menus: first-page model label, selector/AT command parity, help and shared
  serial/web rendering. Evaluate optional ASCII art when the menu is built.
- On-board: NVS, LittleFS and ADC/I2S integration; restore firmware after test apps.
- End-to-end: PC server harness for calls, binary transfer, negotiation, refusal
  and disconnect; controlled DNS/timeout cases. Live `ATDT1` to Amiga Retro.
- Native tests, firmware/LittleFS builds, clang-format and cppcheck must pass.
  Uploads retain the native-test gate. Update README, test matrix, changelog,
  decisions log and roadmap; push and open a draft PR while v0.8 remains incomplete.
- Bench: console **COM15**, Unitek **COM18**, LED and potentiometer connected.
  No MAX3232/DB9 wiring or amp/speaker. Console network acceptance can run now;
  external RS232 acceptance and audio listening checks remain pending wiring.
- Do not run external RS232 tests merely because COM18 exists. Keep the outstanding
  v0.5 cable acceptance explicit, along with v0.8's remaining hardware checks.
