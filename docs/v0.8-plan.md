# v0.8: outgoing calls

Plan updated 25 Oct 2026. One branch: `firmware/v0.8-outgoing-calls`, based on
the merged v0.7. VERSION is bumped once to 0.8; further work on this branch uses it.

## Confirmed identity and speeds

- Jon: identify as a **USRobotics Sportster 14400 Fax**, keeping the existing
  command set and selectable emulated call speeds through **56000**.
- Jon: factory call speed **14400**, represented by `&N8` in every factory template.
- Use later USR V.90 indexes through `&N38`/`&U38`; `&N0` means highest (56000).
  Preserve index meanings 1-16 and saved profiles. Host serial remains 300-115200;
  the maintenance console stays at 115200.
- Identity is modeled pending a verified 14400 ROM capture. Do not present the
  old 33600 ROM details as authentic 14400 details (see `credits/LICENSES.md`).

This preparation is implemented; it can be exercised with `AT*TESTCALL`. It does
not make real outgoing calls available or complete the v0.8 roadmap acceptance.

## Remaining implementation

1. Add hardware-independent phonebook logic and its versioned, CRC-protected NVS
   store. Preload entry `1` with `www.amigaretro.com:23`, by hostname. Preserve exact
   numeric keys, reserved-number exclusions, Telnet/raw mode and optional speed.
   Keep the four `&Z` numbers separate, implement `ATDSn`, retain phonebook through
   `AT&F`/`ATZ`, and include it in recoverable `AT*FACTORY` erasure. Register every
   management command in the shared `AT*` table and help.
2. Add an asynchronous outgoing-call state machine in `lib/`, with DNS/TCP in
   `lib/hw`. Validate before sounds, claim the shared call slot while dialling,
   support `ATD`/`ATDT`/`ATDP`, stored numbers, last-dialled tracking and repeat.
   Bound connection attempts using S7; handle cancellation and clean up on every
   exit. Keep the other local port and the Wi-Fi service responsive.
3. Adapt Zimodem Telnet code with attribution and change notices. Support BINARY
   in both directions, terminal ANSI, window 80x24 and IAC escaping. Raw TCP passes
   bytes unchanged. Preserve backpressure and bounded buffering, including while
   escaped to online command mode. Remote bytes never enter the local AT parser.
4. Integrate `+++`, `ATO`, `ATH`, resets, DTR, flow control, DCD and activity LEDs.
   Apply per-entry speed or `&N`, then implement outgoing `&B0`/`&B2` speed following
   and optional line-speed throttling (default off). The console stays at 115200.
5. Source and verify freely licensed handshake recordings before adding them;
   record provenance, licence and conversions in `credits/LICENSES.md`. Validate
   8 kHz mono, 16-bit PCM WAVs and play them from LittleFS. Keep dial tone -> actual
   dialled DTMF/pulse digits -> handshake -> CONNECT, without ringback. Replace
   blocking call playback with a service that permits cancellation and serial,
   Wi-Fi and pot updates. Support `ATM0/1/2` and `ATL0-3`, amp shutdown when idle,
   and apply the -7 dB cap last. `ATM0` skips the sound delays.
6. Map refusal to BUSY, connection timeout to NO ANSWER, DNS/no Wi-Fi to
   NO DIAL TONE, and remote/Wi-Fi loss after connection to NO CARRIER. Apply the
   existing V/Q/X result filtering and prevent duplicate final results.

Implementation choices still to document: phonebook capacity/management syntax,
throttling command and handshake-file mapping for intermediate rates. Proposed
defaults should be reviewed before depending on them; licensed source availability
also determines which genuine recordings can be bundled.

## Validation and bench limits

- Native: phonebook validation/storage, state transitions, cancellation/deadlines,
  Telnet fragmentation/escaping, flow control/backpressure, speed selection,
  WAV validation and volume. Add meaningful tests before deployment.
- On-board: NVS, LittleFS and ADC/I2S integration; restore firmware after test apps.
- End-to-end: PC server harness for calls, binary transfer, negotiation, refusal
  and disconnect; controlled DNS/timeout cases. Live `ATDT1` to Amiga Retro.
- Native tests, firmware/LittleFS builds, clang-format and cppcheck must pass.
  Uploads retain the native-test gate. Update README, test matrix, changelog,
  decisions log and roadmap; push and open a draft PR while v0.8 remains incomplete.
- Bench: console **COM15**, Unitek **COM18**, LED and potentiometer connected.
  No MAX3232/DB9 wiring or amp/speaker. Console network acceptance can run now;
  external RS232 acceptance and audio listening checks remain pending wiring.
- Do not run external RS232 tests merely because COM18 exists. Keep the outstanding
  v0.5 cable acceptance explicit, along with v0.8's remaining hardware checks.
