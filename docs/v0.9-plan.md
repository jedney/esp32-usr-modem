## Confirmed requirements and bench

- Listen for incoming TCP/Telnet calls on port **23**, with **no caller password**.
- Indicate ringing with RI, the UK ring sound and a flashing AA LED. AA is steady
  on when S0 >= 1 and no call is ringing, off otherwise (brief table 5.4).
- Support manual `ATA` and auto-answer after the number of rings set by S0;
  S0=0 disables automatic answering, not manual answering.
- Remote callers can never reach a local AT parser, command mode, configuration
  screen, hardware tests or any `AT*` handler (Q44/Q79).
- Console: **COM15**, fixed **115200**. Unitek adapter: **COM18**. Jon has an LED
  and potentiometer connected; no other external electronics are wired.
- Current-bench network acceptance uses COM15 and a PC TCP/Telnet client. COM18's
  presence does not make external RS232 tests runnable. MAX3232/DB9/DB25 checks,
  physical RI/DCD and audio listening remain pending wiring. Do not assume that
  the connected LED is AA or that all seven panel LEDs are present.
- Keep all pin definitions in `lib/hw/src/pins.h`, active-low RS232 control outputs,
  the existing final -7 dB sound cap and secret-handling rules.

## Confirmed receiver policy

Manual `ATA` attaches the pending caller to the local port issuing the command;
only one port can win. S0 is shared, so auto-answer needs a deterministic destination.

Jon confirmed on 25 Oct 2026: add **`AT*ANSWERPORT=RS232|CONSOLE`**, default
**RS232**. Include `AT*ANSWERPORT?` to query and `AT*ANSWERPORT=?` to list choices.
This lets the bench select CONSOLE explicitly without guessing from an unwired DTR
input. Do not silently redirect production calls when RS232 is unavailable.

Implemented persistence: save the choice immediately device-wide; retain it through `AT&F` and
`ATZ`, restore RS232 on `AT*FACTORY`, and reject changes while an incoming call is
pending or active. Register it in the shared `AT*` table and `AT*HELP`; record its
future configuration/web parity. Define backward-compatible settings migration and
test persistence/rollback. Current-bench auto-answer acceptance explicitly selects
CONSOLE and restores the previous selection afterwards.

## Implementation sequence

1. **Incoming-call logic and tests in `lib/calls`.** Add a hardware-independent
   incoming controller with a fakeable listener, accepted socket, clock and sound
   interface. Model idle, ringing, answering/handshake and connected states. Reserve
   the shared call slot on accepting the first caller, then transfer ownership to
   the answering `Session` without an unclaimed gap. Reject additional callers
   promptly while ringing, dialling, connected or in online command mode; avoid an
   unbounded pending-client queue. Clean up socket, audio, RI, ring count and slot
   on every failure/cancel/disconnect, so a later call can succeed.
2. **Listener and accepted sockets in `lib/hw`.** Add a nonblocking port-23 listener
   and a safe accepted-descriptor path for the existing socket abstraction. Start
   when Wi-Fi has an address, stop on loss/off, and reopen after reconnect or IP
   change. Bound accept/read/write work per loop, close rejected descriptors and
   expose bind/listen failure on the local console without flooding it. Coordinate
   listener availability with OTA transfers, restart/factory reset and hardware
   tests that take over serial/audio resources. Ringing counts as busy for existing
   OTA, dialling and hardware-test gates; do not interrupt a resource owner.
3. **Ring timing and S-register behavior.** Use the existing generated UK ring:
   400 + 450 Hz, 400 ms on / 200 ms off / 400 ms on / 2000 ms off. Implemented mapping:
   one double-ring cycle is one logical ring, one S1 increment and one local RING
   result; RI follows the audible on portions even under ATM0. Auto-answer on the
   Nth logical ring for S0=N. Drive cadence from elapsed time, independently of
   audio output, including stalled I2S and ATM0. Verify USR S1/reset/DTR conventions
   against primary documentation before finalizing compatibility details; do not
   accidentally persist live S1 through `AT&W`. Use rollover-safe timing, saturate
   counters and avoid catch-up floods after a delayed poll. Keep a manual caller
   pending until answer, local rejection or remote/network loss; do not repurpose
   outgoing S7 as an undocumented ring timeout.
4. **AT and local-session integration.** Add an explicit answer hook to
   `atcmd::Link` / `hostport::Session`; dispatch `ATA` asynchronously without a
   premature OK. `ATA` with no caller must finish deterministically. Deliver RING
   only to eligible local command sessions, obeying Q/V formatting; never inject
   it into another call or a secret prompt. Hook `ATH` and resets into pending-call
   cancellation even though `callUp()` is still false. Test both local ports racing
   to answer and DTR readiness/drop under `&D`/S25. Apply existing operational
   `&N`/`&U`, model-reporting fallback, throttling and host `&B` rules; preserve the
   console's fixed speed. Emit CONNECT once, attach only the winning local session,
   then reuse its `+++`, `ATO`, `ATH`, flow control and carrier-loss lifecycle.
5. **Audio, RI and LEDs.** Extend `CallSound` / `hw::CallAudio` with a ring stage,
   using the existing generated source and streaming volume path. Answering stops
   the ring and may reuse the selected handshake without outgoing dial/digit tones.
   ATM0 skips audio and handshake delays, but still waits for ATA or the S0 threshold.
   Preserve ATM1/2 behavior, live pot/ATL scaling, final cap and amp shutdown on every
   exit. Wire `PanelInput::ringing` in `src/main.cpp` and give the normal RS232 path
   ownership of the incoming controller's RI state; do not fight hardware-test
   overrides. DCD follows established carrier under `&C`, not a merely accepted TCP
   socket. Internal GPIO/I2S checks are distinct from physical acceptance.
6. **Remote data boundary.** Reuse Telnet BINARY negotiation, ANSI terminal type,
   80x24 options and IAC escaping through `TcpConnection`. Treat all remote payload
   as data destined for the selected local terminal. Bound data received before
   answer and while the local side is in online command mode; preserve backpressure
   rather than passing buffered bytes to any parser or dropping them silently.
   Neither remote `+++` nor Telnet control commands may invoke local escape/reset
   behavior. Closing and reusing a connection must not replay old caller bytes into
   a subsequent command session. Do not add a separate raw listener or caller menu
   in this version.
