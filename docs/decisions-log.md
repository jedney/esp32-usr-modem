# Decisions log

The decisions that shape the firmware as it is now, one row each, grouped by topic. Superseded decisions are not kept. Append a row for every new decision or spec change made while coding here, and keep [project-brief.md](project-brief.md) (the firmware spec) in step.

Columns: date, topic, decision, why.

| 2026-10-24 | RS232 polarity and DSR | TTL side of the RS232 Pal is inverted both ways: asserted = LOW. UART1 uses hardware RTS/CTS directly. DTR (input), DCD and RI (outputs) are plain GPIO. DSR is hard-wired on, so `&S` is fixed at 0 | Matches the ESP32 UART's active-low flow control |
| 2026-10-24 | Boot-state resistors | 10 kΩ pull-ups on the four RS232 driver inputs (RXD, CTS, DCD, RI) so the computer sees idle lines while the S3 boots or is flashed. The amp SD pin has no resistor. | Floating GPIOs give garbage or a false carrier |
| 2026-11-13 | On-board RGB LED | The S3 board's WS2812 LED (GPIO47) is not driven. Wi-Fi status is the ARQ LED only | Not visible in the case; `neopixelWrite()` is deprecated in Arduino 3 |
| 2026-11-07 | Speaker and volume | Speaker: Same Sky CLS0361-L152 (8 Ω, 2 W rated, 3 W max, 6.8 Ω minimum), MAX98357A GAIN pin unconnected (9 dB). **No volume cap**: `volume::outputGain()` only clamps the user gain to 0..1. Full-scale single tones may clip slightly at full volume | The cap only cost loudness |
| 2026-11-14 | ARQ LED name | The front-panel label is ARQ/FAX, so `AT*HWLED` and the other LED tests take `FAX` as well as `ARQ` (`hwtest::parseLed`); it is listed in COMMANDS.md and the code and web messages say `ARQ` | An undocumented alias is now a documented one |

## Serial ports and the AT command set

| Date | Topic | Decision | Why |
|---|---|---|---|
| 2026-10-24 | Command set | Standard commands follow the USR Sportster; project commands use `AT*`. `ATI3`-`ATI7` and `ATI9` text comes from a capture of a real Sportster 33600/Fax V2.31 and the USR technical reference; `ATI0` and `ATI1` are placeholders (no capture found). `ATI` text names the model chosen with `AT*MODEL`. `AT+FCLASS=0` gives `OK`, fax classes `ERROR` | Authentic identity so old operating systems detect the modem |
| 2026-10-24 | Defaults | Factory result set is `X4` (all codes); the text is `NO DIAL TONE`. `AT&F` is `AT&F0` (the Sportster's low-performance template); `AT&F1` gives the project defaults (hardware flow control `&H1 &R2`, `&D2`, `&C1`, `&A0` plain `CONNECT`, tone dialling, `&P1` UK pulse ratio, `&S0` fixed). `ATZ` and `AT&F` keep Wi-Fi, passwords, phonebook and the device-wide `AT*` settings | Software that sends `AT&F` expects the USR result |
| 2026-10-24 | Stored templates | Two stored templates as on the Sportster: `&W0`/`&W1` write Y0/Y1, `Yn` picks the power-on template and saves at once, `Z0`-`Z5` reset to them (Y0 = `&F1` and Y1 = `&F2` as shipped). Four stored numbers `&Z0`-`&Z3` for `ATDSn`. `E`, `Q`, `V`, `&C`, `&D` are stored in the templates (a real Sportster takes them from DIP switches). `AT&V` is a project addition showing `ATI4` then `ATI5`. `ATI5` does not pause with "Strike a key when ready" | Authentic structure; no DIP switches in this build |
| 2026-10-24 | Command line | Command lines may be 128 characters (the Sportster takes 58); DEL deletes as well as S5. `S3`, `S4` and `S5` accept 0-127 and `S3` is never printable (32-126); a stored profile that breaks the rule counts as damaged. `AT*SETTING=` takes exactly one setting command | Room for `AT*` arguments; stops a saved `S3` from ending every line |
| 2026-10-24 | Stored settings | NVS namespace `modem`, key `cfg`: one blob with magic `USRM`, layout 1 and CRC-32. A failed read counts as damaged (factory settings, nothing written). Other stores: `net`/`USRN` (Wi-Fi and clock), `device`/`USRA` (password and OTA), `phonebook`/`USRP`, the web, client and Internet records. All are layout 1, CRC-sealed | Safe against half-written data |
| 2026-10-24 | Host speed | The speed is always detected from "AT"/"at"/a lone "A" (300 to 115200, bit time within 6 %). `&B1` (factory) keeps that speed, `&B0` follows the call speed, `&B2` is fixed when answering and follows when calling. `AT*BAUD=<300-115200>` fixes the speed with no detection; `AT*BAUD=AUTO` detects (saved at once). `&W` stores the port's current speed in the template. 8N1 only. `AT*BAUD` from another port is refused while the RS232 port holds the call | Software that sends `AT&B1` expects USR behaviour |
| 2026-10-24 | Speed detection by capture | Detection decodes a recording of the TXD-in pin (RMT receiver: 1 MHz, glitches under 1 µs ignored, a burst ends after 32 ms idle, ping-pong over the S3's 192-symbol memory, bursts queued in a 16 KB FreeRTOS message buffer in PSRAM). In command mode the typing is decoded in software and the UART's copy is thrown away; online, or with a fixed `AT*BAUD`, the UART is used with flow control. Typing reaches the parser about 35 ms late; bytes sent in the 35 ms after a command that goes online can be lost. The capture starts with the port, so a command sent while `setup()` still runs is answered once the loop starts. If it cannot start, the port keeps its speed, reads the UART like a fixed speed and says so once | The core's detection cannot see rates below 9600 on the S3 |
| 2026-11-13 | UART clock | UART1 runs from the 80 MHz bus clock (`Serial1.setClockSource(UART_CLK_SRC_APB)` before every `begin()`), where the S3 copies new baud settings by itself; no register writes from project code | On the crystal clock the S3 needs a manual copy that IDF 6.1 no longer does |
| 2026-10-24 | Flow control | `&H1`/`&H3` use UART1 hardware RTS (CTS drops when the 8 KB buffer and 100 bytes of FIFO are full); `&R2` uses hardware CTS (stop sending while RTS is off); with `&H0`/`&H2` CTS is held on. `&I1`/`&I2` obey XON/XOFF from the computer online (`&I2` strips them); `&H2`/`&H3` send XOFF at 3/4 and XON at 1/4 of the buffer. Host output goes through the UART FIFO without a TX ring (`uart_tx_chars`), so a host that pauses never blocks the loop | USR technical reference meanings |
| 2026-10-24 | Lines and escape | `+++` with a 1 s guard time and `ATO`; `ATO` with no call gives `ERROR`; `ATH`/`ATZ` hang up; `&D2` DTR drop hangs up, `&D3` also resets as `ATZ`; commands are accepted with DTR off (3-wire cables) | Hayes behaviour; init strings work on 3-wire cables |
| 2026-10-24 | Output never waits | Serial result sinks never wait in a loop. Unsolicited output (`RING`) is written whole if the port has room now, otherwise dropped. A reply waits while the computer keeps taking bytes; if no room appears for 250 ms the rest is dropped and the port is marked stalled until it has room again; one write never takes more than 2 s. The policy is `hostport::SinkGate` | A port nobody reads froze the modem for 2 s on every `RING` |
| 2026-10-24 | Information replies | Every information reply starts with S3 S4 (in verbal mode), as the Sportster does, through `Port::beginInfo()`; the configuration screen skips that first line break. `test_console.py` checks every read-only `AT*` command | The reply used to land on the echo line |
| 2026-10-24 | Test call | `AT*TESTCALL[=<seconds>]` makes a test call to a built-in echo (`CONNECT` per `&N`, DCD on, data echoed back, optionally hung up by the far end after `<seconds>`), for bench and client tests | `+++`, `ATO`, DTR and flow control need a call |
| 2026-10-24 | Console output path | Everything the firmware writes to the console goes through `src/console_out.cpp` (UART0 and a 16 KB console log in PSRAM, 1 KB in internal RAM if PSRAM has no room); nothing in `src/` writes to `Serial` directly. IDF log lines are copied in through `esp_log_set_vprintf`. UART0 has a 16 KB transmit buffer in internal RAM so a long reply (`AT*ABOUT` is 9.4 KB) does not hold the loop; more than 16 KB at once still waits for the cable | The network console reads the same log |
| 2026-10-24 | Console and password | The maintenance console is UART0 at 115200 8N1 and the boot banner waits up to 8 s for Wi-Fi when a network is saved, then shows network, signal, IP, `<name>.local` and the clock. Later changes print one line on the console only, in command mode with nothing typed; never on the RS232 or USB port | Host software must not get unexpected text |

## USB modem port

| Date | Topic | Decision | Why |
|---|---|---|---|
| 2026-11-08 | USB modem port | The S3's native USB (GPIO19/20) is a second modem port: a TinyUSB CDC-ACM serial device with its own AT session, configuration screen and Client Tests record, sharing the one call slot. On the board GPIO19/20 are also wired to the rear USB-C power board's D-/D+, so the rear socket carries it. Never connect hosts to the S3's own native USB-C and the rear socket at once. The built-in USB-JTAG debugger is not available while the firmware runs; flash over the UART port or OTA, or hold BOOT and tap RST for the ROM bootloader | A modern PC needs no USB-serial adapter |
| 2026-11-13 | TinyUSB route | `espressif/tinyusb` `==0.21.0~6` (Espressif's release of TinyUSB 0.21.0) from the component registry is a public dependency of the small project component `components/arduino_tinyusb` (Kconfig, a trimmed `tusb_config.h`, CMake); Arduino's own USB layer (`USB.begin`) stays. `lib/hw/src/usb_port.cpp` keeps its own CDC registration, polling and flow control. Not chosen: `espressif/esp_tinyusb` (clashes with Arduino's USB layer over `CONFIG_TINYUSB_CDC_ENABLED`), Arduino's documented lib-builder route (builds TinyUSB master), and Arduino's `USBCDC` class (drops input when full and reboots into the bootloader at 1200 baud). `scripts/sdkconfig_refresh.py` regenerates `sdkconfig` | Newest stable release; least build glue |
| 2026-11-13 | USB reads | `hw::usbRead()`, `usbAvailable()` and `usbDiscardInput()` call TinyUSB only while a computer has configured the device (`tud_ready()`) | With nothing on the rear socket TinyUSB divided by a closed endpoint's packet size of 0 and the modem reset every few seconds |
| 2026-11-14 | USB lines | The USB port sends DCD (`&C`), DSR (always on) and RI (`calls::Incoming::ri()`, on every port as RS232's RI is) as CDC SERIAL_STATE notifications (`CFG_TUD_CDC_NOTIFY 1`), on every change and again when the PC configures the device or opens the port, retried while the endpoint is busy (`hostport::SerialStateSender`). The notification endpoint is a free IN endpoint (`tinyusb_get_free_in_endpoint()`, 0x83), not Arduino's 0x85, which has no transmit FIFO on the S3. On Windows 11 (`usbser.sys`, pyserial 3.5) `.cd` and `.dsr` follow the lines, `.ri` is a level that follows the ring cadence, and `.cts` reads on once a notification has arrived | Retro software sees carrier and ringing as on RS232 |
| 2026-11-14 | USB names | Product name and serial-port (CDC interface) name are the selected model ("US Robotics Sportster 14.4k"); manufacturer "US Robotics"; serial number the Wi-Fi station MAC as 12 upper-case hex digits (`hostport::usbSerialNumber()`, read with `esp_read_mac()`). Vendor and product IDs are Espressif's 303A:1001. Arduino keeps the interface-string pointer, so `modemcfg::productName()` returns a constant; a model change shows after a restart. The serial number keeps one COM port across firmware versions and gives each modem its own | Branding as the Sportster; a stable COM port |
| 2026-11-08 | Answer port | `AT*ANSWERPORT=RS232\|USB\|CONSOLE\|AUTO`, factory AUTO: the first port with DTR on, in the order RS232, USB, console (the console has no DTR, so it is the fallback). A fixed choice never falls back | Answers on whichever computer is connected |
| 2026-11-08 | Client records | Client Tests settings are kept per port: console, RS232 and USB (three CRC-checked records in the `clients` NVS namespace). No automatic terminal identity or named profiles; saving over a record asks for confirmation | One profile per physical port |

## Calls, sounds and answer mode

| Date | Topic | Decision | Why |
|---|---|---|---|
| 2026-10-24 | Dialling | Numeric dial strings: 12 digits = IP on port 23, 13-17 = IP and port, fewer = phonebook or special number; invalid gives `ERROR` before any sound. A quoted string, or one containing `.` or `:`, is a host (`ATDT"host:port"`), so a dotted IP also works. Special numbers: `123` configuration screen, `666` PPP, `667` SLIP, plus Zimodem's `5517546` and `5517545`; reserved numbers cannot be phonebook entries | Old terminal address books reject letters |
| 2026-10-25 | Phonebook | 64 entries, numbers of 1-11 digits, each with host, port, Telnet or raw mode and an optional CONNECT speed; entry 1 is the Amiga Retro BBS (`www.amigaretro.com:23`). Stored as occupied records only (a one-entry book is 92 bytes; the largest is 5,321 bytes and fits NVS beside every other setting with about 600 bytes to spare, checked by `embedded/test_calls`). While the stored book is damaged, edits give `ERROR` until `AT*BOOKCLEAR` | Padded blobs exhausted NVS |
| 2026-10-25 | Model and speed | `AT*MODEL=14400\|28800\|33600\|56000` selects the Sportster series (factory 14.4k), saved at once and kept by `AT&F`/`ATZ`; it sets the `ATI` text and the default CONNECT speed only, not the supported speeds or features. An explicit phonebook speed or `&N` wins; a change takes effect at the next call. `&N`/`&U` use the USR V.90 mapping through index 38. `AT*THROTTLE=ON\|OFF` (factory OFF) limits both data directions to the operational speed | A configurable model and the Sportster speeds |
| 2026-10-25 | Sounds | Handshakes are 8 kHz mono PCM16 WAVs in LittleFS, one each for 1200, 2400, 9600, 14400, 28800, 33600 and 56000 (from Gough Lui's 2016 collection); an intermediate speed uses the nearest lower file and 300 uses 1200. Dial tone, DTMF, busy, ring and pulse clicks are generated in firmware with UK tones (dial 350+450 Hz, busy 400 Hz 0.375 s on and off, ring 400+450 Hz 0.4 on, 0.2 off, 0.4 on, 2.0 off, pulse 10 per second) | Supplied recordings and UK tones |
| 2026-11-14 | Call sound level | The generated call tones (dial, ring, busy, carrier, DTMF; also their previews in the configuration screen) are cut by `volume::kCallToneDb` (-10.5 dB) in `hw::CallAudio`, so the two-tone sounds play at the handshake recordings' RMS (about -16.5 dBFS; they were -6 dBFS) and the single tones (busy, carrier) 3 dB above. The recordings stay as they are (modem noise has a crest factor of about 14 dB and their peaks already sit at -2 dBFS). Pulse clicks, the hardware test and calibration tones (`AT*HWTEST`, `AT*HWPOT=TONE`, the sweep) stay at full scale. `test_hwtest` checks the levels by RMS. The constant is tuned by ear on the bench | The generated sounds were 10 to 13 dB louder than the recordings |
| 2026-10-27 | Call timing | Outgoing call: dial tone, digits, ringback for `AT*RINGDELAY` ms (default 1500) while TCP connects, the handshake WAV, a pause of `AT*CONNECTDELAY` ms, then `CONNECT`. Both values are 0-60000 ms (0 disables), device-wide, kept by `ATZ`/`AT&F`, and read at call start. The socket is serviced during the pause; a remote hang-up or keypress gives `NO CARRIER`; `S7` does not apply to the pause; `ATM0` connects at once. `S7` limits only the wait for the network connection | A call should sound like a modem |
| 2026-10-27 | Hostname dial | Dialling a host name (not a phonebook number or IP address) starts DNS during the dial tone, then plays the IPv4 address digits as DTMF or pulses and connects to that address with no second lookup. A lookup failure, or no answer within `S7` of the start, gives `NO DIAL TONE`; `ATM0` and `ATM3` skip the lookup step | Host names have no digits to play |
| 2026-10-25 | Result mapping | Refused or reset while connecting: `BUSY` with the busy tone; timeout: `NO ANSWER`; DNS failure or no Wi-Fi: `NO DIAL TONE`; remote drop on an established call: `NO CARRIER` | Authentic result codes |
| 2026-10-25 | Telnet | Telnet by default (BINARY both ways, terminal type `ANSI`, window 80x24), overridable per phonebook entry; raw passes bytes unchanged. Replaces Zimodem's blocking reads with a bounded incremental parser. Storms are bounded and a full send queue stops reading | Safe against a hostile server |
| 2026-10-25 | Answer mode | Listen on port 23 with no password. One UK double ring is one logical ring: `RING` on every port, RI follows 400/200/400/2000 ms even with `ATM0`, `S1` counts when `S0` is set. A pending caller reserves the shared slot; auto-answer never falls back to another port or interrupts a partial command or password prompt. An unanswered call is dropped after 8 rings (`S0` above 8 counts as 8). Every call socket has TCP keepalive (idle 60 s, 10 s interval, 6 probes), so a dead peer ends in `NO CARRIER` after about 2 minutes | A caller who never hangs up held the line |
| 2026-10-25 | Remote isolation | Remote bytes pass only through bounded Telnet and data queues to the chosen local session. Only locally received bytes can invoke the escape or the AT parser. A remote caller can never reach command mode, `AT*` commands or the configuration screen | The port is open to the LAN |
| 2026-10-26 | Call slot | One call slot, shared by RS232, USB, the console and the browser. A configuration screen on any of them reserves it, so incoming callers are turned away while one is open; entry is refused while another menu or a call holds it. | 2026-10-26 | Internet dial-up | PPP (`ATDT666`) and SLIP (`ATDT667`) on a private /30 (default 10.64.64.1 modem, 10.64.64.2 client) with NAT to Wi-Fi, any PPP login, unfragmented IPv4 with a 1500-byte serial MTU, NAPT ports 32768-49151, and no firmware ping during the call. **PPP, SLIP and NAPT stay on raw lwIP**: Arduino 3.3's `PPP` class is an `esp_modem` client (DTE), while this modem is the DCE; `esp_netif` has no SLIP. `CONFIG_ARDUINO_SELECTIVE_PPP` stays off | The tested engine (`lib/internet`, pppd interop) stays |
| 2026-10-26 | Call history and logs | The last 50 calls are kept in CRC-sealed LittleFS files (primary, temporary, backup; load order file, temporary, backup; atomic rename); a LittleFS image replacement removes them. Structured debug events are kept in 256 KiB of PSRAM (4 KiB fallback) and are events only, never typed text, passwords or call data | NVS has no room for history |
| 2026-10-26 | Export | `AT*EXPORT` prints an allowlist of settings as `AT` commands (profiles, phonebook, per-port client commands that need local confirmation), never the Wi-Fi or device password | Restore without exposing secrets |

## Wi-Fi, clock and security

| Date | Topic | Decision | Why |
|---|---|---|---|
| 2026-10-24 | Wi-Fi | One saved network, DHCP or static IP, mDNS name `usr-modem` (configurable, `usr-modem.local`), power save off. `AT*WIFIJOIN` asks for the password at a masked prompt (`*` per character, nothing with `E0`; Esc or Ctrl-C cancels), so the password is never on the command line. It joins for up to 20 s and saves only on success; on failure the previous network is rejoined. A background reconnect retries at once, then after 5, 10, 20, 30 s and every 60 s. `AT*WIFISCAN` and `AT*WIFIJOIN` and `AT*WIFIIP` are refused while any port has a call up | A typo must not lock the modem off the network |
| 2026-11-13 | Wi-Fi code | Scans use `WiFi.scanNetworks()` in the background with the modem's own 15 s limit (Arduino 3 ignores scans it did not start); events are registered with `Network.onEvent()`; link state and reason are set together under a lock; a scan with Wi-Fi off switches the radio off again; the driver's own flash store of the network is off (`WiFi.persistent(false)`); passphrases accept any byte except control bytes, 8-63 bytes or 64 hex digits | Arduino 3 behaviour |
| 2026-10-24 | Clock | NTP (`pool.ntp.org` default) with the clock in UTC; local time comes from the project's own POSIX-rule code with a table of 16 named zones (`AT*TZ=?`), or any POSIX rule (`Mm.w.d` only). Default Pacific/Auckland. The offset is cached and worked out again only in a new minute or when the zone changes | No time-zone database on the ESP32 |
| 2026-10-25 | Device password | One login `admin` for the web page, the network console and OTA. A random 12-character password (about 56 symbols, no look-alikes) is generated at first boot and shown in the boot banner until it is first used (a web, console or OTA login) or changed; afterwards only hashes are stored: SHA-256 for OTA, MD5 of `admin:usr-modem:password` for the web's Digest (the realm stays `usr-modem`). `AT*PASS` changes it without the old one: alone it generates and shows a new one once on the requesting local port; `AT*PASS=<text>` sets 8-32 printable characters. Never allowed from a remote caller or the browser; never in a log, export or web message. `AT*FACTORY` erases it | One credential for every network service |
| 2026-11-11 | Secrets rule | The device password is shown in the boot banner until first use and once on the requesting local port when `AT*PASS` generates one. It is never shown to the browser, logged, exported or sent to the web page, and never on a remote (port 23) session. Sensitive `AT*` rows mask their arguments, wipe their line buffers and refuse `A/` | Lets the owner read a generated password without it reaching any other path |
| 2026-11-13 | OTA | `ArduinoOTA` uses only the password hash, recreated on a password, host name or IP change; its own mDNS handling is off so the Wi-Fi responder owns `.local`. The hash is SHA-256 of the device password (64 hex characters) and the sign-in is PBKDF2-HMAC-SHA256; no MD5 compatibility. `scripts/ota_upload.py` speaks the protocol itself (UDP invitation, TCP image transfer on port 32320), signs in once with SHA-256 only and refuses a modem that asks for MD5 or no password. `scripts/allow_ota.ps1` opens that return port for PlatformIO's Python from the local subnet. `AT*OTA=ALWAYS\|DEMAND` (saved) and `AT*OTA=ON\|OFF` (a 10-minute demand window); the listener pauses during calls, joins and scans. The device record is 142 bytes (password 33, OTA hash 65, Digest hash 33, CRC 4) | Arduino 3.3 deprecates MD5 password hashes |
| 2026-10-25 | Factory reset | `AT*FACTORY` needs Y and Enter within 30 s on the issuing local port; N, Esc, Ctrl-C or a time-out cancels. A durable reset marker precedes erasure of `modem`, `net`, `device` and the other stores, so an interrupted reset retries at boot; it finishes even with LittleFS unmounted. Commands are blocked after the erase until the reboot, which generates a new device password. ESP calibration data is kept | No partial resets |
| 2026-11-13 | Network console | The maintenance console over raw TCP port 2001 (like ser2net), factory ON, plain TCP with no TLS, `AT*NETCONSOLE=ON\|OFF`. It asks for the device password first (checked against its SHA-256 hash in constant time; a wrong one locks every log-in out for a second, three close the connection, 60 s to log in, 64 characters at most). Before the prompt it sends the selected model and the modem's status, one per line (sent 250 ms after connecting, because pyserial's `socket://` empties its input just after connecting). After log-in it replays the last 16 KB of console output and shares the console session, counted as a local console: it shows what the cable shows, password lines included. A new connection gets its own prompt, and when it logs in the earlier client is told and closed, so a hung client never keeps anyone out. Output never waits: a client that stops reading misses output and is told how much. TCP keepalive 10 s idle, 3 probes 2 s apart. It listens only with Wi-Fi up and device credentials set. Port 23 callers are unaffected | Debug and flash over Wi-Fi while the USB cable is on the modem port |

| 2026-10-26 | Web server | The bundled ESP-IDF HTTP server on port 80, HTTP only, login `admin` and the device password with Digest authentication, CSRF tokens, a Host-header check (the modem's name and IP) and a Content-Security-Policy. A WebSocket ticket (`GET /api/session`, single use, 30 s) lets the page open `/ws`. A correct response for an expired or replayed nonce gets a new challenge with `stale=true`, so browsers retry without asking again. A wrong response starts a 1 s lock-out in which every attempt is answered `401` unchecked (refused attempts do not extend it). The HTTP receive time-out is 1 s. | 2026-11-13 | Web server on IDF 6.1 | IDF 6.1 answers the WebSocket upgrade itself, so the upgrade is checked (Host, Origin, ticket) and the client attached in the route's `ws_pre_handshake_cb` (`CONFIG_HTTPD_WS_PRE_HANDSHAKE_CB_SUPPORT`); a refused upgrade gets 403. The header gate checks the raw bytes as they pass (one Host, no duplicate Origin/Authorization/Content-Length/Upgrade/X- header, no Transfer-Encoding, no bytes after the body, at most 4 KiB). Every HTTP response carries `Connection: close` and the server does not close the connection itself: the browser does, and the server then frees the slot. The server has 12 slots (`max_open_sockets`) in a system of 24 sockets (`CONFIG_LWIP_MAX_SOCKETS`) and 40 active TCP connections (`CONFIG_LWIP_MAX_ACTIVE_TCP`). WebSockets use `TCP_NODELAY` | A page load is 14 files, each with a 401 and an authorised request on its own connection, beside up to three WebSockets. With six slots the server's least-recently-used purge closed requests in progress. A close queued after each response (`httpd_sess_trigger_close`) names a table slot, not a connection, and the server runs one queued job per pass, so after a burst it closed the next connection that reused the slot (browser: `ERR_CONNECTION_RESET`, a red connection and several tries to enter the configuration screen). Shutting down the sending side instead left a connection in TIME_WAIT under an open socket, which lwIP reclaims when it runs short of connections, and the later close freed it twice (a panic in the `tcpip` task). Without `TCP_NODELAY` a response waited 50 ms per piece |

A LittleFS image replaces the sounds, web files and call history. Refused during a call.
