## Scope and release boundary

Deliver a usable local configuration terminal through both `AT*CONFIG` and
`ATDT123`, with one hardware-independent model for screens, settings, help and
actions. ANSI with 7-bit ASCII art is the default; CP437 and plain monochrome are
selectable. Show the selected Sportster model prominently on the first page.

Include status, phonebook, all existing settings with help, command reference,
About, sounds, debug logging, persistent last-50 call history, Wi-Fi tools, clock,
updates, password change, password-free configuration export, restart/factory-reset
confirmation and hardware tests. Expose S0 and `AT*ANSWERPORT` together.

Client Tests are a visible, unavailable item explaining that they arrive in v0.13;
do not implement terminal probing or file transfers here. Browser transport, login
and upload UI remain v0.11. Keep the model usable by that future transport, including
Unicode box-drawing output for the browser's CP437 style.

## Confirmed configuration-session policy

Jon confirmed on 26 Oct 2026: reserve the shared call slot for either local
configuration session (USB console or RS232). Reject entry
while a call is pending/active (including online command mode), and reject incoming
callers while the menu owns the slot. This gives one predictable resource owner and
avoids an auto-answer or hardware test taking over an interactive menu.

This resolves and extends the brief's proposed RS232-only busy policy. Release the
reservation on every exit, cancellation or failure; a second local menu cannot
claim the occupied slot. Phonebook dialing transfers ownership to the outgoing call.
Simultaneous serial/browser sessions are also only Proposed and are not required here.

## Architecture and implementation order

1. **Shared action catalogue and parity tests.** Add a configuration library in
   `lib/` with no Arduino calls. Give each setting/action a stable ID, label, help,
   argument validation, secret/confirmation metadata, availability policy and
   concrete `AT*` invocation. Move the production star-command registry out of
   `src/main.cpp` into host-testable shared data, using injected service adapters.
   Reuse existing modem/network/device/phonebook operations; do not create a second
   settings implementation. Add `AT*` wrappers for standard-only operations such as
   profile/register editing and dialing so the literal parity rule holds. Enumerate
   every editable profile field and S-register, device/network setting, stored
   template and stored number; show effective persistence behavior in its help.
   Display-only containers and navigation are not commands; every feature action is.
   Test real registry lookup, arguments, handler binding and context restrictions,
   including concrete HW subcommands behind the existing prefix dispatcher.

2. **Terminal controller and renderers.** Add bounded input handling, line editing,
   paging, back/help/quit and separate ANSI/ASCII, ANSI/CP437 and plain renderers.
   Start with 80x24 usable content, paginate long lists, and avoid requiring cursor
   keys, function keys or terminal detection. Accept CR/CRLF, Backspace and DEL;
   support single-key numbered/lettered choices. Keep terminal style local to its
   session for this version and expose an `AT*` style command. Do not send CP437
   bytes through UTF-8 conversion on serial. Escape control characters in displayed
   SSIDs, hosts, filenames and logs so stored/network text cannot inject ANSI.
   Render in bounded chunks with backpressure; a slow 300-baud terminal must not
   stall Wi-Fi, OTA, serial servicing or the other port. Refresh live status without
   overwriting typed input; plain mode uses explicit refresh rather than escape codes.

3. **Session lifecycle and reserved dialing.** Extend `hostport::Session` input
   routing explicitly for local menu ownership, rather than feeding menu input into
   the AT parser. `AT*CONFIG` opens immediately and silently. Route the already
   classified special config number through the dialer: `ATDT123` plays the existing
   dial/digit/short-handshake sequence and emits one CONNECT before the screen.
   Preserve ATM/ATL, pot, cap, cancellation, host-speed and result-code conventions.
   Define and test quit, hang-up, local guarded escape/ATO for the dialed form,
   DTR drop, reset and failed start; release reservations and stop audio on every
   exit. Direct entry must not claim a fictitious network carrier. Phonebook dial
   transfers menu ownership to the outgoing call without a reservation gap and
   returns to normal command mode on completion. Remote bytes remain exclusively
   call payload, even while a local terminal is escaped; no remote menu entry.

4. **Core screens and shared commands.** Implement status snapshots (panel states,
   Wi-Fi/IP/RSSI, call host/mode/speed/duration/byte counts, host settings), phonebook
   CRUD/dial, settings/help, command reference and update controls using shared
   services. Keep existing model/throttle/answer-port persistence and rollback
   semantics. Maintain a concrete screen/action-to-command inventory in the tests.
   Proposed new command families include `AT*CONFIG`, `AT*STATUS`, `AT*SETTING`,
   `AT*DIAL`, `AT*REFERENCE`, `AT*ABOUT`, `AT*SOUNDS`, `AT*PLAY`, `AT*LOG`,
   `AT*CALLLOG`, `AT*PING`, `AT*DNS`, `AT*EXPORT` and `AT*RESTART`;
   finalize exact argument/query forms in that inventory before coding handlers.
   Register every command in `AT*HELP`; preserve existing commands as compatible
   entry points. Restart and factory reset require cancellable confirmation with a
   timeout; password forms use existing masked, wiped, non-repeatable secret input.

5. **Debug and reset diagnostics.** Implement a hardware-independent bounded log
   ring using storage supplied by `lib/hw`: approximately 256 KiB in PSRAM. Define
   verbosity/query/view/clear commands and stable snapshot/paging behavior across
   wraparound. On missing/allocation-failed PSRAM, report reduced capacity explicitly
   and use a small bounded fallback; never consume unbounded internal heap. Log
   structured events, not raw AT input or call payload: Wi-Fi/device passwords must
   never enter the ring, serial logging, crash records or export. Keep SDK diagnostics
   from bypassing this policy. Persist reset reason and an available bounded crash
   record through hardware adapters; distinguish absent crash information. Do not
   continuously stream logs to flash or print unsolicited logs over an active menu.

6. **Persistent call history.** Add a versioned, validated last-50 record store
   behind an injected storage interface, separate from modem profiles and phonebook.
   Capture incoming/outgoing lifecycle events exactly once, including failed calls,
   result, timestamp, number/host, duration and directional payload bytes. Mark time
   unavailable until synchronized; measure durations monotonically. Exclude internal
   config calls and test calls from real network history. Use bounded atomic writes
   on call completion, not every data chunk; retain the last valid store after power
   loss/corruption or write failure. History survives restart; factory reset erases
   it through the existing reset-store mechanism. Test capacity, eviction, duplicate
   cleanup events, corrupted/truncated records and scratch-NVS space limits.

7. **Export, About, sounds and Wi-Fi tools.** Generate About data reproducibly from
   the licensing record, including concept credits and used/reference/planned status;
   do not imply planned components are bundled. Generate safe, ordered restore AT
   commands for active/stored profiles, stored numbers, phonebook and device/network
   settings, excluding both passwords and password-bearing join commands. Respect
   parser line lengths and supported escaping; report values that cannot be restored
   faithfully rather than emitting executable malformed commands. Round-trip with a
   fresh store and synthetic credentials. List generated tones and LittleFS audio
   files, including the generic handshake attribution; play through the existing
   capped audio path with cancellation and resource checks. Implement bounded,
   cancellable ping/DNS diagnostics through `lib/hw`, with native fakes, timeout and
   Wi-Fi-loss handling. Reuse existing scan/join/time/OTA/password services.

8. **Hardware tests screen.** Adapt `src/hwconsole.cpp` through context-aware input
   and output adapters so results go to the initiating local session. Console offers
   every test; RS232 lists line/loopback/bridge as unavailable with the Q79 reason.
   Guided testing on RS232 skips those steps explicitly. Enforce restrictions in
   handlers as well as menu visibility, including equivalent line-control paths;
   no caller gets a hardware handler. Distinguish the menu's own reservation from
   another active RS232 session when deciding whether a console test may take over
   UART1. Restore LEDs, UART/flow settings, amp and signal ownership on all exits.

## Implementation and acceptance record (26 Oct 2026)

- The shared registry, action catalogue, profile/register help, paged terminal,
  reserved-number dialer, structured log ring, call journal and export/replay
  commands are implemented in `lib/config`. Both local sessions reserve the same
  call slot. Direct entry has no network carrier; dialed entry reuses local
  escape/ATO/DTR behavior and existing capped audio.
- Terminal rendering is bounded to 32 KiB per response and pages at 18 lines.
  ANSI/CP437 status refreshes every two seconds; plain mode refreshes explicitly.
  Long responses report truncation; debug-ring reads are bounded to 8192 bytes and
  accept offsets. A log query is copied before paging, so later events do not
  change the displayed snapshot. SDK raw diagnostics stay suppressed at every level.
- History uses CRC-checked LittleFS primary/temporary/backup files, with old-file
  recovery and atomic rename, rather than NVS. This avoids the space pressure of
  two full phonebook/history blobs in the existing 20 KiB NVS partition. History
  survives firmware-only updates and restarts; a full filesystem-image upload
  replaces it along with other LittleFS contents. Factory reset erases its files.
- `AT*RESETINFO` reports persisted reset reasons and only bounded numeric summary
  fields from an available core dump. It never exports raw memory. About is
  regenerated from the licensing record during builds; no new external assets or
  libraries were introduced. C++17 is explicit for native and ESP32 builds.
- Export restores both templates and their framing/speeds, active modem settings,
  stored numbers, complete phonebook, model/throttle/receiver and network/OTA
  settings. Network credentials are supplied separately through the masked join.
  `AT*PROFILE`, `AT*PROFILECTL`, `AT*EXPLICIT`, `AT*BOOKCLEAR` and
  `AT*RESTOREEND` support deterministic replay; final speed/framing changes are
  acknowledged at the previous settings. Native replay tests use a fresh store.
- Final software checks: 312/312 native checks pass through the actual upload gate;
  four host-script checks pass; clean firmware build succeeds (85,104 bytes static
  RAM, 995,965 bytes application flash). Formatting/version validation pass and
  cppcheck reports no high or medium findings. All eight on-board programs compile.
- Bench: all 43 on-board checks pass, including the four new PSRAM/history/probe/audio
  cases and history backup recovery after primary-file corruption. The first log
  wrap assertion generated fewer bytes than the ring capacity; doubling its input
  corrected the test and the complete on-board run passes. No firmware defect was
  hidden by relaxing a check.
- Normal v0.10 firmware is restored through a clean COM15 USB upload and all 312
  native checks. An existing PlatformIO serial monitor was closed to release COM15.
  Configuration acceptance: nine pass, one skip (48.75 s). This covers all terminal
  styles, local dialing/escape/ATO, menus/help, incoming rejection, secret-free export,
  restart cancellation, loopback DNS/ICMP and sound cancellation. Its first-start
  fixture now allows the firmware's bounded Wi-Fi boot wait.
- Existing console and local incoming/outgoing regressions are running. No COM18,
  external BBS, credential rotation, real Amiga rendering or physical audio/signal
  acceptance is claimed. The ESP32/LED/pot-only bench is confirmed; existing
  v0.5/v0.8/v0.9 physical gaps remain open.
