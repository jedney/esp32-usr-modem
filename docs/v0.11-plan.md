## Confirmed session policy

Jon confirmed on 26 Oct 2026: **one active menu; read-only browser status when
busy**. This extends v0.10's serial-menu reservation policy to the browser:

- One interactive configuration owner across console, RS232 and browser. A browser
  owner reserves the same call slot and rejects incoming calls, like a serial menu.
- An authenticated browser can view read-only live status while a call or another
  menu owns the modem. It cannot execute commands, start tests or upload. Show why
  editing is unavailable and offer an explicit attempt to enter when the slot frees.
- A second browser starts as a bounded read-only observer; it cannot take over the
  first session. No automatic promotion or replay of keystrokes after reconnect.
- Browser phonebook dial transfers the reservation to an outgoing call through the
  shared dialer, then shows status while that call owns the slot. Define explicitly
  which local session receives payload; do not accidentally create a browser BBS
  data terminal merely by reusing a serial `Session`.

Ownership is decided. Browser dial payload destination remains an implementation
design item to resolve explicitly before routing calls; this session decision does
not select a serial receiver or add a browser BBS terminal.

## Implementation order

### 1. Compatibility and transport boundaries

- Evaluate the maintained ESP32Async ESPAsyncWebServer/AsyncTCP pair against the
  installed Arduino 2.0.x/ESP-IDF 4.4 toolchain. Pin a verified compatible pair in
  `platformio.ini`; do not silently upgrade the core or select an archived fork.
  Prove hashed Digest auth, WebSocket upgrade interception, fragmented frames,
  streamed upload callbacks and connection cleanup in a small build first.
- Check the chosen version's actual authentication/replay behavior, request limits
  and callback ordering. Library defaults are not evidence that these protections
  are present. Add the required policy around the transport where necessary.
- Put hardware-independent request/auth/session/update state machines in a new
  `lib/webinterface/` (or equivalently scoped library). Put Wi-Fi/server, crypto,
  filesystem and Update calls in `lib/hw` adapters. Use fake clocks, RNG, storage,
  connections and update writers for native tests.
- Keep network callbacks short on core 0. Pass bounded input/events to the core 1
  modem owner, which alone changes menu/call/UART/audio state. Publish immutable
  status snapshots back; do not invoke the global command registry concurrently.
- Set finite connection/token counts, request/frame/input/output limits and idle
  timeouts. Coalesce replaceable status; apply terminal backpressure and disconnect
  persistently stalled peers without blocking serial, audio or call servicing.
- Add third-party licences/notices to `credits/LICENSES.md` and generated About.

### 2. Authentication, request policy and web enable setting

- Persist web enabled by default in a versioned settings format, with migration,
  rollback on storage failure, factory-reset cleanup and secret-free export.
  Provide `AT*WEB[?]` and `AT*WEB=ON|OFF`, shared-menu entry and `AT*HELP` parity.
  Disabling closes listeners, tokens and sessions; console/RS232 can re-enable it.
- Check Host before serving assets, issuing tokens, upgrading or accepting any
  upload bytes. Accept only the configured `<name>.local` and current modem IPv4,
  with the valid port-80 authority form. Normalize case safely; reject malformed,
  missing, duplicate or unrelated authorities and traversal/encoded-path variants.
- Digest only: fixed user `admin`, realm `usr-modem`, using the existing stored
  HA1 from `Device::digestHash()`, never a plaintext password reconstruction.
  Bound nonce lifetime and replay state; validate method/URI/qop/cnonce/nc and
  reject incorrect/replayed responses. Bound failed-login work and connection use.
- On the first successful authenticated use, call `Device::markUsed()`; fail closed
  if its persistence fails. Failed challenges must not consume boot disclosure.
  Password rotation/factory reset revokes outstanding nonces, tokens and sockets.
- Every asset, status endpoint and error body containing device data requires auth.
  Use an explicit gzip asset allowlist with correct MIME/Content-Encoding; never
  expose arbitrary LittleFS files, history or credentials through a catch-all path.
- Set CSP and no-sniff/frame/referrer policies in HTTP headers. Keep scripts local;
  restrict browser connections to this modem. Sensitive/session replies are
  `no-store`; do not add permissive CORS or put credentials/tokens in diagnostics.

### 3. Session endpoint, WebSocket and shared terminal

- Implement `GET /api/session` and `/ws?token=...` exactly as the protocol specifies:
  unpredictable single-use token, 30-second monotonic expiry, bounded outstanding
  tokens, atomic consumption at a valid upgrade. Validate the browser Origin against
  the modem authority before consuming it; refuse absent/foreign browser origins.
- Associate the connection with its authenticated capability and CSRF token. All
  state-changing HTTP requests require Digest and the session-bound CSRF header.
  Terminal changes over binary frames are protected by the validated Origin and
  single-use authenticated upgrade capability; preserve binary terminal framing
  rather than inventing an incompatible JSON keystroke envelope.
- Send `hello`, initial LED/call/Wi-Fi/clock snapshots, then terminal output. Decode
  binary input incrementally across frame boundaries; bound paste/fragments and
  reject invalid protocol/control data. Unknown client text messages cannot invoke
  actions. Use RFC-compliant close/ping/pong handling through the chosen adapter.
- Add an explicit trusted-browser context to the shared terminal/session interfaces.
  Replace `menuOf()`'s current console-versus-RS232 fallback, and every equivalent
  two-port assumption; browser commands must never reach console output by accident.
- Reuse the action catalogue, parser validation, masked prompts and paging with a
  UTF-8 renderer. Test split multibyte characters and literal CP437 conversion,
  displayed-text escaping, secret masking under E/F variations and bounded output.
- Browser password change must be write-only. Existing bare `AT*PASS` prints a
  generated password to its local port: disable that disclosure in browser context
  or provide a write-only set form using the same service. Never return plaintext
  device/Wi-Fi passwords or hashes to xterm, JSON, logs, export or upload replies.
- On disconnect, quit, Wi-Fi loss, web disable, reset or credential rotation, cancel
  prompts/tests and release only that session's reservations/resources. Reconnect
  obtains a fresh token and screen; it never repeats pending input or confirmations.

### 4. Live status and Wi-Fi rollback

- Publish the actual panel mask after overrides/stretching: AA/CD/RD/SD/TR/CS/ARQ,
  on change and at most 20 Hz. Browser traffic must not generate RD/SD activity.
- Publish complete call transitions including incoming, dialling, ringing, escaped
  calls and configuration. Preserve current-call model speed and byte accounting.
  Use `since=0` when UTC is unavailable; do not invent a timestamp after NTP sync.
- Send Wi-Fi on change/every 10 seconds while up; clock on connect/every 60 seconds
  and time/zone changes, using the existing timezone rules and epoch-zero behavior.
  JSON-escape all external strings and allowlist status fields to exclude secrets.
- Browser network changes need the brief's 60-second revert policy. Extend the
  existing serial join's 20-second operation without changing its established
  behavior: keep a previous-settings transaction and deadline outside the socket
  lifetime, commit only on successful connection, and restore on failure/timeout.
  Cover DHCP/static/hostname effects and save failures, not just SSID/password.
  Intentional Wi-Fi OFF/forget needs explicit warning/confirmation before loss of
  browser access; serial recovery remains available. No captive setup portal.

### 5. Browser hardware tests

- Refactor `src/hwconsole.cpp` blocking loops into cooperative, cancellable test
  jobs or an equivalent bounded service that keeps transport and modem servicing
  alive. Add a browser Term adapter; output/input stay on the initiating terminal.
- Expose all Q79 tests. Line/loopback/bridge and equivalent HWSIG paths require
  exclusive idle UART1 ownership, checked again at start, not merely hidden in UI.
  The owning browser menu's reservation is allowed; another menu/call/partial
  RS232 command is not. Suspend and restore UART1 and line-control state safely.
- Show live DTR/RTS with on-screen DCD/RI/CTS controls using the shared actions;
  keyboard controls may remain in xterm. Bridge COM18 traffic to browser terminal
  bytes with bounded queues and Ctrl-X exit. Give loopback-plug instructions before
  running the physical loopback test; a wired adapter is not a loopback plug.
- Keep RS232 menus' line/loopback/bridge exclusions and remote-caller isolation.
  Restore LEDs, UART/flow settings, signals, amp and audio ownership after every
  completion/cancel/disconnect. All playback retains the final -7 dB cap.

### 6. Browser firmware and LittleFS upload

- Extend `web/PROTOCOL.md` before coding the upload UI: define target selection,
  content type/length, project/version metadata, CSRF header, confirmation tokens,
  progress/success/error semantics and reboot/reconnect behavior. Keep raw release
  `firmware.bin`/`littlefs.bin` usable; add reproducible companion metadata if needed.
- A first build spike must verify project identity/version metadata in the actual
  PlatformIO app image. Do not assume Arduino's app descriptor already contains
  this project's name/version. Embed an unambiguous marker if needed; reject
  bootloader/merged/wrong-chip/wrong-project/oversized/truncated images.
- Generate an image manifest for LittleFS too: it has no ESP app descriptor. Define
  how its project, format/version, length and integrity are verified against the raw
  image, with build-script tests and server validation. A filename or browser-only
  check is insufficient. Settle this before enabling filesystem writes.
- Downgrades require an explicit confirmation bound to target, image identity and
  version. Compare project versions numerically (0.11 is newer than 0.9); decline
  unknown versions without explicit handling. Never infer target from filename alone.
- Authenticate, validate Host/Origin/CSRF and acquire one global update reservation
  before any flash write. Recheck idle atomically; refuse during pending/active
  calls, serial menus or hardware tests. Allow the owning browser Updates screen
  without mistaking its own reservation for a call. Serialize against ArduinoOTA,
  new dial/answer attempts, reset and all other filesystem writers/readers.
- Stream bounded chunks through the existing Update library into the inactive app
  slot; select it only after complete validation. Handle timeout/disconnect/abort,
  write/size/checksum failures and duplicate submissions without rebooting into a
  partial image. Persist authenticated-use bookkeeping before installation.
- LittleFS is the single `spiffs` data partition, not an inactive app slot. Stop
  playback/history/static-file handles, quiesce filesystem users and unmount before
  replacement. Its contents include sounds, web assets and persistent call history;
  warn and confirm replacement, including history loss, before uploading.
- There is no second filesystem partition: do not promise atomic replacement or
  rollback after interruption. Determine identity validation timing and destructive
  failure behavior explicitly. On invalid/partial filesystem, do not auto-format;
  boot with console/USB recovery available and a small authenticated recovery page
  compiled into firmware if feasible. Verify recovery by USB filesystem upload.
- Browser updates use tested release artifacts; the PlatformIO upload test gate
  remains mandatory for development uploads. Add CI checks for image metadata and
  manifests and document firmware/filesystem compatibility and upload order.

## Implementation and acceptance record (26 Oct 2026)

- Used the bundled ESP-IDF HTTP server/WebSocket support already enabled in Arduino
  2.0.17, with core-0 network callbacks and bounded queues into the modem loop.
  No server dependencies or core upgrade were needed. The portable `webinterface`
  library owns Digest parsing/replay policy, tickets, header validation, settings,
  image identity checks and CP437 conversion. `lib/hw/web_service` owns sockets,
  entropy/hashing and flash access. Menu buffers use PSRAM with bounded fallback.
- Login uses the existing HA1, user admin and realm usr-modem. The real-device
  test caught IDF 4.4 emitting its automatic upgrade before the route handler;
  validation now happens in a receive gate before that handshake. The gate rejects
  duplicate/security headers and pipelining, bounds raw headers to 4 KiB and passes
  only needed fields into the core's fixed 1 KiB parser. Live invalid-Origin and
  token-reuse checks pass. Listener shutdown uses a borrowed global context with
  a no-op free callback; serial OFF/ON and reservation release are verified.
- One browser menu reserves the same call slot as serial. Other browsers show live
  read-only status; E requests entry and does not replay old input. Browser dialing
  transfers the call to the idle RS232 host, which receives CONNECT and payload.
  Write-only browser password changes reuse the existing handler; bare generated
  password disclosure is refused in browser context. The menu exposes model, S0,
  receiver and WEB settings with AT* parity and includes WEB in export/reset.
- Hardware tests service transport during waits. Browser line controls and bridge
  run through the shared handlers; Ctrl-X/disconnect cancel and return ownership.
  The real Unitek sees DCD/RI/CTS toggles, and manual DTR/RTS changes appear in the
  browser. The fixture disables the adapter's automatic RTS flow control only for
  that manual-input check, then restores it. ASCII bridge traffic passes both ways.
- Browser joins use a 60-second candidate deadline, retained independently of the
  socket. IP changes have a rollback guard. Join storage failure restores the old
  network before reporting success; serial joins retain their 20-second behavior.
- Application identity is linked into firmware; the filesystem build embeds an
  identity file. Uploads check target, project/version, size and full SHA-256 before
  activation. Downgrades and filesystem replacement require image-bound confirmation.
  LittleFS uses blank-run staging in the unused app slot, refusing insufficient
  staging space before touching the live filesystem. A final-copy power failure
  still requires USB recovery; the partition is never auto-formatted. Release CI
  checks both raw image identities and includes a length/SHA manifest.
- Software evidence: all 328 native checks, 18 JavaScript checks and six script
  checks pass. cppcheck has no high/medium findings. Both images build and pass the
  identity-manifest validator. The two new on-board checks pass, and all nine
  on-board programs compile without uploading the bare-board tests. Latest measured
  image size and memory details are in the build logs; the app remains about 1.07 MB,
  static RAM is 142,096 bytes and web assets about 132 KiB compressed. The running
  board reports about 158 KiB free internal heap and 7.5 MiB free PSRAM.
- Wired v0.10 baseline: all 21 RS232 checks pass in 170.36 s. The original 300-baud
  ATI4 timeout budget covered only command length; it now includes the full profile.
  No firmware baud-detection relaxation was needed. Initial web backend acceptance:
  nine pass, one opt-in upload skipped, one filesystem-asset case deselected
  (27.38 s). Real isolated Chrome login shows Online/v0.11, with no uncaught page
  errors. Desktop/narrow screenshots of the new local preview also pass visual QA.
- Firmware-only HTTP acceptance passes (22.36 s): the candidate was verified,
  installed and rebooted into v0.11. The test sends a fresh Digest before the large
